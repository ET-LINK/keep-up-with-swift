# Swift Club

**English** · [简体中文](README.zh-CN.md)

An interactive guide to the new features in Swift 6.0–6.4, drawn as a metro map: <https://et-link.github.io/swift-club/>

Each station covers one feature, with old and new code side by side and real compiler output. The site also has three labs, a Guess the Compiler quiz, an index of Swift Evolution proposals, and a short Swift 5.x concurrency primer.

## Run

Open `index.html` in a browser. No server needed.

## Build

Every Swift snippet is compiled or run with the local `swiftc` at build time, and its output is embedded as is. A snippet that should fail but compiles, or the reverse, fails the build.

```bash
node tools/build.mjs                # rebuild, recompiling only changed snippets
node tools/build.mjs --fresh        # ignore the cache
node tools/build.mjs --no-compile   # use the cache only, no swiftc
```

You need Node 18+ and a Swift toolchain (on macOS, Xcode for the Swift Testing examples). The compile cache `tools/.compile-cache.json` is committed, so a change that leaves the code blocks alone can be built without Swift using `--no-compile`.

Code-block attributes (`check=error`, `flags="…"`, `expect="…"`, …) are documented at the top of `tools/build.mjs`.

## Layout

```
content/<lang>/   lessons (5.x.md … 6.4.md), labs, challenges, site.json, ui.json
src/page.html     page shell
assets/           style.css, app.js, generated data.<lang>.js
tools/            build.mjs, Swift Evolution snapshot, compile cache
dist/             single-file build for publishing; use index.html locally
```

`index.html`, `assets/data.*.js` and `dist/swift-club.html` are generated by the build. Don't edit them by hand.

## Deploy

GitHub Pages publishes the root of `main`. Rebuild, commit the generated files with your change, and push; it goes live in a minute or two. `.nojekyll` keeps Pages from running Jekyll over the Markdown in `content/`.

There's no CI build because the compiler output depends on the Swift version.

## Sources
