## nonisolated-types
title: "`nonisolated` can modify types and extensions"
line: 1
se: 0449
level: key
short: nonisolated types
tags: nonisolated extension MainActor inference protocol conformance prevent global actor inference
tldr: Until now `nonisolated` could only go on a single property or method. Now it can go on a whole `extension`, freeing every member inside it from actor isolation at once; on a type, it also stops the compiler from inferring a global actor automatically.

```swift title="Before: every member needs its own nonisolated" check=ok
@MainActor
struct Product {
    var name: String
    var price: Double
}

extension Product: CustomStringConvertible, Equatable {
    nonisolated var description: String { "\(name) $\(price)" }
    nonisolated static func == (a: Product, b: Product) -> Bool { a.name == b.name }
}
```

```swift title="Swift 6.1: one nonisolated extension does it" check=ok hl="7"
@MainActor
struct Product {
    var name: String
    var price: Double
}

nonisolated extension Product: CustomStringConvertible, Equatable {
    var description: String { "\(name) $\(price)" }
    static func == (a: Product, b: Product) -> Bool { a.name == b.name }
}
```

Another use is blocking “isolation inference”. A type that conforms to a `@MainActor` protocol is automatically inferred to be `@MainActor`, so using it anywhere else needs `await`:

```swift title="Conforming to a @MainActor protocol: the type is quietly inferred as main-actor isolated" check=error
@MainActor protocol Screen {}

struct Settings: Screen {
    var theme = "dark"
    func export() -> String { theme }
}

func backup(_ s: Settings) -> String {
    s.export()
}
```

```swift title="Refusing the inference explicitly with a nonisolated struct" check=ok
@MainActor protocol Screen {}

nonisolated struct Settings: Screen {
    var theme = "dark"
    func export() -> String { theme }
}

func backup(_ s: Settings) -> String {
    s.export()
}
```

## taskgroup-infer
title: Task groups infer their result type
line: 1
se: 0442
level: brief
short: TaskGroup inference
tags: withTaskGroup TaskGroup inference of: child task
tldr: The `of:` in `withTaskGroup(of: Int.self)` can now be omitted; the compiler infers the child tasks' result type from the closure passed to `addTask`.

```swift title="Before: of: is required" check=run
let total = await withTaskGroup(of: Int.self) { group in
    for n in 1...5 { group.addTask { n * n } }
    var sum = 0
    for await square in group { sum += square }
    return sum
}
print(total)
```

```swift title="Now: omit of:" check=run hl="1"
let total = await withTaskGroup { group in
    for n in 1...5 { group.addTask { n * n } }
    var sum = 0
    for await square in group { sum += square }
    return sum
}
print(total)
```

By the way, this uses `for await` instead of `group.reduce(0, +)`. Calling a `nonisolated async` method like `reduce` directly on the main actor “sends” the task group to another thread, and in Swift 6 mode that reports `sending 'group' risks causing data races`. That is exactly the problem [6.2's nonsending](#f-nonsending) solves.

## trailing-commas
title: Trailing commas almost everywhere
line: 3
se: 0439
level: key
short: Trailing commas
tags: trailing comma comma parameter list tuple generic capture list diff
tldr: Array and dictionary literals have always allowed an extra comma after the last element. Swift 6.1 extends that to parameter lists, argument lists, tuples, generic parameter lists, closure capture lists, and string interpolations.

The biggest benefit is cleaner diffs: adding or removing the last parameter changes only one line. Code generators (macros, plugins) also no longer need to treat the last item specially.

```swift check=run
func makeLabel(
    text: String,
    size: Double,
    bold: Bool,          // ← parameter list
) -> String {
    "\(text)·\(size)·\(bold)"
}

let label = makeLabel(
    text: "Swift",
    size: 17,
    bold: true,          // ← argument list
)

let point = (
    x: 1,
    y: 2,                // ← tuple
)

struct Pair<
    First,
    Second,              // ← generic parameter list
> {}

let show = { [label, point,] in    // ← capture list
    print(label, point)
}
show()
```

Condition lists are the exception: `if a, b, { }` is still not allowed, because the trailing comma would make `{` ambiguous.

```swift title="An if condition list can't have a trailing comma" check=error script
let a = true, b = false
if a, b, {
    print("not allowed")
}
```

## metatype-keypaths
title: "Metatype key paths: key paths can point at static properties"
line: 3
se: 0438
level: brief
short: Static key paths
tags: keypath key path static static property metatype
tldr: Write `\Theme.Type.accent` to get a key path to a static property, used exactly like a key path to an instance property.

```swift check=run
struct Theme {
    static let accent = "orange"
    static let font = "SF Pro"
}

let accentPath = \Theme.Type.accent
print(Theme.self[keyPath: accentPath])

let all: [KeyPath<Theme.Type, String>] = [\.accent, \.font]
print(all.map { Theme.self[keyPath: $0] })
```

## objc-implementation
title: "`@objc @implementation`: implement Objective-C classes in Swift"
line: 5
se: 0436
level: key
short: "@implementation"
tags: Objective-C objc implementation mixed-language migration header category
tldr: Keep the header as it is, and replace the `@implementation` in the `.m` file with a Swift extension marked `@objc @implementation`. A legacy codebase can migrate to Swift one class, one category at a time.

```objc file=MyView.h check=none
// the header is unchanged; Objective-C and Swift callers keep working as before
@interface MyView : NSView
- (void)reload;
@end
```

```swift title="MyView.swift: write the implementation in Swift" check=none
@objc @implementation
extension MyView {
    func reload() {
        print("reload, implemented in Swift")
    }
}
```

The compiler checks that the Swift implementation matches the declarations in the header one to one: a missing implementation, an extra one, or a mismatched signature is an error. To implement a category, write `@objc(CategoryName) @implementation extension MyView`.

## member-import
title: Member import visibility
line: 3
se: 0444
flag: MemberImportVisibility
level: brief
short: Member imports
tags: import visibility extension MemberImportVisibility
tldr: Until now, if **any one file** in a module imported another module, the methods that module adds through extensions were available in **all files**. With `MemberImportVisibility` on, only files that actually write the `import` can see those members.

```swift file=Report.swift check=none
// Another file, A.swift, has import FancyStrings (which extends String with shout())

// Report.swift does not import FancyStrings:
let title = "hello".shout()
// before: compiles (quietly depends on another file's import)
// with MemberImportVisibility on: an error, with a hint to add import FancyStrings
```

This makes dependencies honest: deleting one file no longer makes another file fail to compile for no obvious reason, and it avoids ambiguity between same-named extension methods from different modules.

## warning-flags
title: "Precise control over warnings: `-Werror` and diagnostic groups"
line: 6
se: 0443
level: brief
short: Warning groups
tags: warnings -Werror -Wwarning warnings-as-errors diagnostic group
tldr: It used to be “treat all warnings as errors” or none. Now you can control them **per diagnostic group**, for example upgrading every warning to an error except “deprecated API”, which stays a warning.

```shell check=none
# treat all warnings as errors, except “use of a deprecated API”, which stays a warning
swiftc -warnings-as-errors -Wwarning DeprecatedDeclaration main.swift

# upgrade just one group of warnings to errors
swiftc -Werror DeprecatedDeclaration main.swift
```

A group's name is the name in square brackets at the end of a compiler diagnostic. You can see them all over the real compiler output on this site, such as `[#DeprecatedDeclaration]` and `[#RegionIsolation]`, and each group has an official documentation page. From 6.2 SwiftPM can set them too (see [6.2](#f-swiftpm-62)), and 6.4 lets you control them right in source code with [`@diagnose`](#f-diagnose).

## package-traits
title: SwiftPM package traits
line: 6
se: 0450
level: key
short: Package traits
tags: SwiftPM package traits conditional compilation optional dependencies Embedded WebAssembly
tldr: A package can declare a number of “traits” that its users turn on or off as needed. Traits control conditional compilation and optional dependencies, so one package can offer different capabilities on servers, embedded devices, WebAssembly, and so on.

```swift file=Package.swift check=none
// swift-tools-version: 6.1
import PackageDescription

let package = Package(
    name: "Logging",
    traits: [
        .trait(name: "JSON", description: "Log in JSON format"),
        .trait(name: "Embedded", description: "Trim features for embedded environments"),
        .default(enabledTraits: ["JSON"]),       // JSON is on by default
    ],
    targets: [
        .target(name: "Logging"),
    ]
)
```

```swift title="Client side: turn on only the traits you need" check=none
.package(url: "https://github.com/example/logging", from: "1.0.0", traits: ["Embedded"])
```

```swift title="Inside the package: a trait is a compilation condition" check=none
#if JSON
func format(_ message: String) -> String { #"{"msg": "\#(message)"}"# }
#else
func format(_ message: String) -> String { message }
#endif
```

## testing-61
title: "Swift Testing: scoping traits and inspectable errors"
line: 6
level: brief
short: Test scoping
tags: Swift Testing TestScoping trait #expect throws error setUp tearDown
tldr: "`#expect(throws:)` and `#require(throws:)` now return the error they caught, so you can inspect it further; custom traits conforming to `TestScoping` can run setup and cleanup logic before and after a test."

```swift check=ok testing
import Testing

enum LoginError: Error, Equatable {
    case wrongPassword(attemptsLeft: Int)
}

func login(_ password: String) throws(LoginError) {
    throw .wrongPassword(attemptsLeft: 2)
}

@Test func reportsAttemptsLeft() {
    let error = #expect(throws: LoginError.self) {
        try login("123456")
    }
    #expect(error == .wrongPassword(attemptsLeft: 2))   // the return value is the error itself
}

struct MockServer: TestTrait, TestScoping {
    func provideScope(
        for test: Test,
        testCase: Test.Case?,
        performing function: @Sendable () async throws -> Void
    ) async throws {
        print("Starting mock server")
        try await function()
        print("Stopping mock server")
    }
}

extension Trait where Self == MockServer {
    static var mockServer: Self { Self() }
}

@Test(.mockServer) func fetchProfile() async {
    #expect(true)
}
```
