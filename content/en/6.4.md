## async-defer
title: "`defer` can `await` now"
line: 1
se: 0493
level: core
short: async defer
tags: defer async await cleanup resource close asynchronous
tldr: In an async function, a `defer` block can now contain `await`. When the scope exits, the async cleanup is waited for in full before the function actually returns.

To do async cleanup before, you had to write it by hand ahead of every `return` and `catch`, or start a `Task { }` inside `defer`, which guarantees neither the execution order nor that it finishes before the function returns.

```swift title="Async cleanup is guaranteed to run too" check=run
struct Connection {
    func send(_ message: String) async throws { print("Sending:", message) }
    func close() async { print("Connection closed") }
}

func sync(over connection: Connection) async throws {
    defer { await connection.close() }
    try await connection.send("Hello")
    try await connection.send("Goodbye")
}

try await sync(over: Connection())
```

`await` can only appear in a context that is itself `async`; the `defer` of a synchronous function still can't suspend:

```swift title="Not in a synchronous function" check=error
func cleanup() async {}

func work() {
    defer { await cleanup() }
    print("Working")
}
```

## cancel-shield
title: "Cancellation shields: `withTaskCancellationShield`"
line: 1
se: 0504
level: core
short: Cancellation shield
tags: cancellation shield Task isCancelled cleanup defer
tldr: After a task is cancelled, network requests and file writes in its cleanup code often give up early because they “see the cancellation”. Wrap them in `withTaskCancellationShield { }` and the code inside runs to completion as if the task had not been cancelled.

```swift check=run
func flushLogs() async {
    print("  Cancellation state seen while uploading logs:", Task.isCancelled)
}

let task = Task {
    try? await Task.sleep(for: .seconds(10))      // wakes up immediately once cancelled
    print("Was the task cancelled?", Task.isCancelled)
    await withTaskCancellationShield {
        await flushLogs()                           // inside the shield, the cancellation is “invisible”
    }
}
task.cancel()
await task.value
```

It pairs perfectly with [`async defer`](#f-async-defer), and that is exactly how the official release notes use it:

```swift title="However you exit, finish reporting the metrics" check=ok
func uploadMetrics(for path: String) async {}
func parse(_ path: String) async throws {}

func processFile(at path: String) async throws {
    defer {
        await withTaskCancellationShield {
            await uploadMetrics(for: path)     // runs to completion even if the task has been cancelled
        }
    }
    try await parse(path)
}
```

- The shield does **not** stop the task from being cancelled; it only makes the code inside the shield unable to observe the cancellation. After you leave the shield, `Task.isCancelled` is still `true`.
- Child tasks created inside the shield (`async let`, task groups) aren't automatically cancelled either.
- Put only cleanup that truly must finish in there; don't use it to “ignore cancellation”.

## task-unused
title: A discarded “throwing Task” gets a warning
line: 1
se: 0520
level: brief
short: Task warning
tags: Task warning error swallow discardableResult throws unused
tldr: "If nobody keeps the return value of `Task { try await … }`, any error thrown inside it is silently swallowed. 6.4 warns about this; a `Task` that doesn't throw is unaffected."

```swift title="The error is silently swallowed" check=warning
struct UploadError: Error {}
func upload() async throws { throw UploadError() }

func start() {
    Task {
        try await upload()
    }
}
```

```swift title="Handle the error inside the task, or discard it explicitly" check=ok
struct UploadError: Error {}
func upload() async throws { throw UploadError() }

func start() {
    Task {
        do { try await upload() } catch { print("Upload failed:", error) }
    }
    _ = Task { try await upload() }      // explicitly say “I don't care about the result”
}
```

## tilde-sendable
title: "`~Sendable`: explicitly declare “I am not Sendable”"
line: 1
se: 0518
level: brief
short: ~Sendable
tags: Sendable ~Sendable non-Sendable audit subclass unchecked
tldr: Until now, “not `Sendable`” could only be expressed by writing nothing, so you couldn't tell an audited, deliberate choice from a forgotten annotation. Now you can write `~Sendable` to say explicitly “this type isn't thread-safe”.

```swift check=ok
public class Pipeline: ~Sendable {          // audited: the base class itself is not thread-safe
    var stages: [String] = []
}

final class LockedPipeline: Pipeline, @unchecked Sendable {
    // the subclass protects its state with a lock itself, so it may be declared Sendable
}
```

`~Sendable` also stops the compiler from inferring `Sendable` automatically for structs and enums, and it silences false positives from checks that require “every public type to declare Sendable explicitly”.

## continuation
title: "The new `Continuation`: a continuation that can't be resumed twice"
line: 1
se: 0528
level: key
short: Continuation
tags: Continuation withContinuation CheckedContinuation UnsafeContinuation callback bridging resume ~Copyable
tldr: "The `Continuation` that `withContinuation` provides is `~Copyable`, and `resume` consumes it. “Resuming twice” is a compile-time error, with none of `CheckedContinuation`'s runtime overhead."

```swift title="Store a waiter and resume it later" check=run
actor Doorbell {
    private var waiter: Continuation<String, Never>?

    func wait() async -> String {
        await withContinuation(of: String.self) { continuation in
            waiter = consume continuation           // move it into the stored property
        }
    }

    func ring(_ visitor: String) {
        waiter.take()?.resume(returning: visitor)   // take() removes it and leaves nil, so it is resumed at most once
    }
}

let bell = Doorbell()
async let visitor = bell.wait()
try? await Task.sleep(for: .milliseconds(50))
await bell.ring("Courier")
print(await visitor)
```

```swift title="Resume twice? A compile-time error" check=error
func twice() async -> Int {
    await withContinuation(of: Int.self) { continuation in
        continuation.resume(returning: 1)
        continuation.resume(returning: 2)
    }
}
```

However, a typical “callback-style API” takes an escaping closure, and the compiler can't guarantee that an escaping closure runs exactly once, so a noncopyable continuation can't be consumed inside one:

```swift title="It can't be consumed inside an escaping closure" check=error
func legacyFetch(_ done: @escaping @Sendable (String) -> Void) { done("data") }

func fetch() async -> String {
    await withContinuation(of: String.self) { continuation in
        legacyFetch { value in continuation.resume(returning: value) }
    }
}
```

In that situation you can convert it to a `CheckedContinuation(continuation)`, with runtime checks as the safety net. If the new type is destroyed without having been resumed, it triggers a `fatalError` directly, instead of leaving the task that is waiting on it suspended forever.

## optional-some
title: "`some P?`: optional opaque and existential types without parentheses"
line: 3
se: 0521
level: key
short: some P?
tags: some any opaque existential optional parentheses
tldr: You used to have to write `(some Shape)?` and `(any Shape)?`; now `some Shape?` and `any Shape?` mean the same thing.

```swift check=run
protocol Shape {
    var area: Double { get }
}

struct Square: Shape {
    var side: Double
    var area: Double { side * side }
}

func largest(_ sides: [Double]) -> some Shape? {     // before: (some Shape)?
    sides.max().map { Square(side: $0) }
}

let shape: any Shape? = largest([2, 5, 3])           // before: (any Shape)?
print(shape?.area ?? 0)
```

Composition types still need parentheses to remove ambiguity: write `any (P & Q)?`, while `any P & Q?` is still an error. For the difference between `some` and `any`, see the [5.x basics](#f-some-any).

## diagnose
title: "`@diagnose`: control one class of warnings in source"
line: 6
se: 0522
level: key
short: "@diagnose"
tags: diagnose warning diagnostic group ignored error deprecated
tldr: "`@diagnose(group, as: ignored/warning/error)` changes the level of one group of warnings only within the annotated declaration: silence it in legacy code that is mid-migration, or upgrade a warning to an error on a critical path."

```swift title="Ignore “deprecated” warnings in this function only" check=warning
@available(*, deprecated, message: "Use newAPI() instead")
func oldAPI() {}

@diagnose(DeprecatedDeclaration, as: ignored, reason: "Being migrated; removed in the next release")
func legacyBridge() {
    oldAPI()          // no warning here anymore
}

func elsewhere() {
    oldAPI()          // everywhere else still warns as usual
}
```

```swift title="The other way around: upgrade a warning to an error in critical code" check=error
@available(*, deprecated)
func oldAPI() {}

@diagnose(DeprecatedDeclaration, as: error)
func paymentFlow() {
    oldAPI()
}
```

A group's name is the name in square brackets at the end of a diagnostic (for example the `[#DeprecatedDeclaration]` in the output above). The command-line `-Werror` / `-Wwarning` ([6.1](#f-warning-flags)) set the global default; `@diagnose` overrides it locally on top of that, and nested declarations can override again.

## memberwise-private
title: The memberwise initializer is no longer held hostage by private properties
line: 3
se: 0502
level: brief
short: Memberwise init
tags: memberwise init initializer private struct default value
tldr: As soon as a struct has one `private` property with a default value, the compiler-generated memberwise initializer becomes entirely `private` and unusable from outside. From 6.4 such properties are excluded from the initializer's parameters.

```swift check=run
struct Article {
    var title: String
    var author: String
    private var viewCount = 0           // a private property with a default value

    var summary: String { "\(title) / \(author) / views \(viewCount)" }
}

// Before 6.4: the generated init(title:author:viewCount:) is private, and this line is an error
let article = Article(title: "What's new in Swift 6.4", author: "Keep Up with Swift")
print(article.summary)
```

For compatibility, the old initializer signature that includes every property is still available in existing language modes (where it was already accessible).

## borrow-mutate
title: "`borrow` / `mutate` accessors: read and write properties without copying"
line: 2
se: 0507
level: core
short: borrow·mutate
tags: borrow mutate accessor get set _read _modify copy ~Copyable performance
tldr: "A computed property's `get` always returns a **copy**: wasteful for big values and flatly impossible for noncopyable ones. A `borrow` accessor lends out the storage directly, and a `mutate` accessor hands out a mutable reference directly."

```swift check=run
struct Sensor: ~Copyable {
    var readings: [4 of Double] = [0, 0, 0, 0]
}

struct Station: ~Copyable {
    private var _sensor = Sensor()

    var sensor: Sensor {
        borrow { return _sensor }        // lend it out read-only, no copy
        mutate { return &_sensor }       // hand out a mutable reference to modify in place
    }
}

var station = Station()
station.sensor.readings[2] = 36.6       // goes through mutate
print(station.sensor.readings[2])       // goes through borrow
```

- Before, the standard library used underscored `_read` / `_modify` coroutine accessors internally; `borrow` / `mutate` need no coroutine and cost less.
- For cases where you need to run code before and after the access (such as taking a lock), there are `yielding borrow` / `yielding mutate` from another proposal.
- The 6.4 release notes specifically mention that a property can use these to expose a `Span` or `InlineArray` directly for reading and modification.

## noncopyable-protocols
title: "Noncopyable types can be `Equatable`, `Comparable`, and `Hashable` too"
line: 2
se: 0499
level: brief
short: ~Copyable protocols
tags: Equatable Hashable Comparable ~Copyable ~Escapable protocol borrowing
tldr: The standard library changed the requirements of `Equatable`, `Comparable`, and `Hashable` to use `borrowing` parameters, so noncopyable and nonescapable types can conform to them.

```swift check=run
struct AccessKey: ~Copyable, Hashable {
    let raw: UInt64

    static func == (a: borrowing AccessKey, b: borrowing AccessKey) -> Bool {
        a.raw == b.raw
    }

    func hash(into hasher: inout Hasher) {
        hasher.combine(raw)
    }
}

let k1 = AccessKey(raw: 42)
let k2 = AccessKey(raw: 42)
print(k1 == k2, k1 != AccessKey(raw: 7))
```

Note: `Set` and `Dictionary` still require copyable elements, so noncopyable types can't go in them yet.

## unique-box-array
title: "`UniqueBox` and `UniqueArray`: heap memory with a single owner"
line: 2
se: 0517, 0527
level: core
short: UniqueArray
tags: UniqueArray UniqueBox Box heap ownership ~Copyable copy-on-write COW vector Vec unique_ptr
tldr: "`UniqueArray` is a dynamic array with no copy-on-write and no reference counting, whose elements may be noncopyable; `UniqueBox` puts a value on the heap and owns it exclusively. Both are `~Copyable`, so assignment is a **move**."

```swift check=run
struct Frame: ~Copyable {
    let index: Int
    deinit { print("Freed frame \(index)") }
}

func render() {
    var frames = UniqueArray<Frame>()         // elements may be noncopyable
    frames.append(Frame(index: 1))
    frames.append(Frame(index: 2))
    print("\(frames.count) frames in total")

    var buffer = UniqueBox<[1024 of UInt8]>(.init(repeating: 0))   // put 1 KB on the heap
    buffer.value[0] = 0xFF
    print("First byte:", buffer.value[0])
}                                              // leaving the scope: freed automatically

render()
```

- `UniqueArray` is like C++'s `std::vector` and Rust's `Vec`: it grows automatically but always has exactly one owner, and `let b = a` invalidates `a`.
- `UniqueBox` is like `unique_ptr` / `Box<T>`: good for very large values (avoiding stack copies) or recursive data structures.
- For ordinary business code, `Array` is still the first choice; these two types target performance-sensitive code that needs determinism.

## ref
title: "`Ref` and `MutableRef`: first-class references"
line: 2
se: 0519
level: key
short: Ref
tags: Ref MutableRef reference borrow inout ~Escapable lifetime
tldr: "`borrowing` and `inout` can only appear on parameters. `Ref` / `MutableRef` turn “borrowing” into a value you can store in a local variable and pass around, with its lifetime checked by the compiler."

```swift check=run
struct Settings: ~Copyable {
    var volume = 50
}

func demo() {
    var settings = Settings()

    do {
        var editor = MutableRef(&settings)   // borrows settings exclusively
        editor.value.volume += 10
        // while editor is alive, settings can't be accessed directly
    }
    print(settings.volume)

    let viewer = Ref(settings)               // shared borrow: read-only
    print(viewer.value.volume)
}

demo()
```

Both are `~Escapable` and can't outlive the value they refer to. Think of them as a safe version of pointers: “dangling” and “aliasing conflicts” are both ruled out at compile time.

## iterable
title: "`Iterable`: borrowing iteration"
line: 2
se: 0516
level: key
short: Iterable
tags: Iterable Sequence for-in iteration borrowing iterator ~Copyable InlineArray UniqueArray Span
tldr: "A `Sequence`'s iterator has to **copy** each element out, so noncopyable elements can't be iterated. The new `Iterable` protocol lends out elements a `Span` at a time, so `for-in` neither copies nor consumes."

```swift check=run
struct Ticket: ~Copyable {
    let seat: String
}

var tickets = UniqueArray<Ticket>()
tickets.append(Ticket(seat: "3A"))
tickets.append(Ticket(seat: "7C"))

for ticket in tickets {          // borrow one at a time: no copy, no consumption
    print("Seat", ticket.seat)
}

let rgb: [3 of UInt8] = [255, 128, 0]
for channel in rgb {             // not possible in 6.2; now InlineArray can be iterated with for-in directly
    print(channel)
}
```

An `Iterable`'s iterator hands out a run of contiguous elements at a time through `nextSpan()`, which is also easier to optimize for types backed by contiguous memory (arrays, `InlineArray`). It also supports typed-throws iteration through the `Failure` type.

## temp-alloc
title: "`withTemporaryAllocation`: temporary memory without touching pointers"
line: 2
se: 0524
level: brief
short: Temp memory
tags: withTemporaryAllocation OutputSpan temporary stack scratch buffer pointer unsafe
tldr: To get a temporary buffer you used to have to use `withUnsafeTemporaryAllocation` and raw pointers. The new function gives you an `OutputSpan`: just `append` elements, and it is cleaned up automatically afterwards.

```swift check=run
let total = withTemporaryAllocation(of: Int.self, capacity: 4) { output in

```

## rawspan-load
title: "`RawSpan`: read bytes as typed values, safely"
line: 2
se: 0525
level: brief
short: Reading bytes
tags: RawSpan bytes load parsing binary ConvertibleFromBytes
tldr: Read a `UInt16` or `UInt32` out of a run of raw bytes without any unsafe pointer API. Only types for which “any bit pattern is valid” (such as integers) may be read this way.

```swift check=run
// A simple binary header: version (UInt16), flags (UInt16), length (UInt32), little-endian
func parseHeader(_ packet: [UInt8]) -> (UInt16, UInt16, UInt32) {
    let bytes = packet.span.bytes                           // RawSpan
    return (
        bytes.load(fromByteOffset: 0, as: UInt16.self),
        bytes.load(fromByteOffset: 2, as: UInt16.self),
        bytes.load(fromByteOffset: 4, as: UInt32.self),
    )
}

print(parseHeader([0x01, 0x00, 0x03, 0x00, 0x2A, 0x00, 0x00, 0x00]))
```

Behind it are two new marker protocols: `ConvertibleFromBytes` (every bit pattern is a valid value, such as integers) and `ConvertibleToBytes` (no padding bytes, so it can safely be viewed as bytes). Types with “invalid bit patterns” or semantic constraints, such as `Bool`, pointers, and `Range`, don't conform to them.

## trivially-identical
title: "`isTriviallyIdentical(to:)`: tell in constant time whether it's “the same storage”"
line: 4
se: 0494
level: brief
short: Fast identity
tags: isTriviallyIdentical identical equality performance copy-on-write COW memoize cache
tldr: "`Array`, `String`, `Dictionary`, and other types gain `isTriviallyIdentical(to:)`: it only checks whether the underlying storage is the same one, in O(1). `true` guarantees they are equal; `false` guarantees nothing."

```swift check=run
let a = Array(1...100_000)

```

A typical use is the fast path for caching and UI refreshes: when the input is “obviously unchanged”, reuse the last result, and otherwise fall back to the full `==` comparison.
