## c-interop
title: "`@c`：让 C 直接调用 Swift"
en: C compatible functions and enums
line: 5
se: 0495
level: core
short: "@c"
tags: C interop 互操作 cdecl @_cdecl 头文件 header 嵌入式 FFI @implementation
tldr: 给全局函数或枚举加上 `@c`，编译器就会按 C 的调用约定生成它，并把声明写进生成的头文件，C/C++ 代码直接 `#include` 就能调用。它取代了长期“非官方”的 `@_cdecl`。

```swift title="MathKit.swift" check=ok
@c(MathKit_clamp)                       // 可以指定 C 侧的名字
public func clamp(_ value: CInt, _ low: CInt, _ high: CInt) -> CInt {
    min(max(value, low), high)
}

@c
public enum Direction: CInt {           // 必须有 C 兼容的整数原始值类型
    case north, south
}
```

```c title="编译器生成的头文件（真实输出节选，来自 swiftc -emit-clang-header-path）" check=none
typedef SWIFT_ENUM(int, Direction, closed) {
  DirectionNorth = 0,
  DirectionSouth = 1,
};

SWIFT_EXTERN int MathKit_clamp(int value, int low, int high) SWIFT_NOEXCEPT SWIFT_WARN_UNUSED_RESULT;
```

反过来，如果 C 头文件里**已经有**一个函数声明，可以用 `@c @implementation` 在 Swift 里写它的实现。编译器会核对两边的签名是否一致：

```c title="geometry.h：已有的 C 声明" check=none
double area_of_circle(double radius);
```

```swift title="geometry.swift：用 Swift 实现" check=none
@c @implementation
func area_of_circle(_ radius: Double) -> Double {
    .pi * radius * radius
}
```

- 枚举的 case 在 C 侧会变成“类型名 + 首字母大写的 case 名”，比如 `DirectionNorth`。
- 同一版本还允许 `@objc` 用在全局函数上，签名可以使用 Objective-C 类型。
- 推荐模式：在 `@c` 函数外面再包一层安全的 Swift API，例如接受 `Span` 而不是指针加长度（6.4 的发布说明专门推荐了这种做法）。

## module-selectors
title: "模块选择器 `Module::name`"
en: Module selectors for name disambiguation
line: 3
se: 0491
level: key
short: 模块选择器
tags: module selector 模块 命名冲突 :: 同名 歧义 disambiguation
tldr: 两个导入的模块都有同名 API？写 `ModuleA::getValue()` 明确指定从哪个模块查找。自己的类型和标准库重名时，用 `Swift::` 就能拿到标准库的那个。

```swift title="自己定义的 Task 和标准库重名了" check=run
struct Task {
    var title: String
}

let todo = Task(title: "写周报")            // 我们自己的 Task

let job = Swift::Task {                     // 标准库的并发 Task
    print("后台处理：", todo.title)
}
await job.value
```

以前遇到这种冲突，只能写 `Swift.Task`。但如果某个模块恰好有一个叫 `Swift` 的类型，或者模块名和其中的类型同名（比如 `XCTest.XCTest`），点语法就会失效。`::` 永远只表示“模块”，没有歧义：

```swift check=none
import ModuleA
import ModuleB

let x = ModuleA::getValue()     // 调用 ModuleA 的 getValue
let y = ModuleB::getValue()     // 调用 ModuleB 的 getValue
```

## perf-attrs
title: 库作者的三把优化扳手：`@specialized`、`@inline(always)`、`@export`
en: Explicit specialization, inline(always) & definition visibility
line: 2
se: 0460, 0496, 0497
level: key
short: 优化控制
tags: specialize specialized inline always export implementation interface 优化 optimization 泛型 库 library 性能
tldr: 三个属性，让库的作者控制编译器如何优化“调用我的代码”：为泛型预生成特化版本、保证内联、把函数实现暴露给调用方。

```swift check=ok
extension Sequence where Element: BinaryInteger {
    @specialized(where Self == [Int])        // 为 [Int] 预先生成特化版本
    @specialized(where Self == [UInt8])
    public func total() -> Int {
        reduce(0) { $0 + Int($1) }
    }
}

@inline(always)                              // 保证每个直接调用点都被内联
public func fastAbs(_ x: Int) -> Int {
    x < 0 ? -x : x
}

@export(implementation)                      // 把函数体提供给调用方，便于跨模块优化
public func clampPercent(_ x: Double) -> Double {
    min(max(x, 0), 100)
}
```

| 属性 | 作用 | 取代 |
| --- | --- | --- |
| `@specialized(where …)` | 在库里为常用类型预先生成泛型特化；通用版本在入口处检查类型并转发到特化版本 | `@_specialize` |
| `@inline(always)` | 保证直接调用会被内联；做不到时报错，而不是悄悄忽略 | `@inline(__always)` |
| `@export(implementation)` | 函数体对调用方可见，调用方可以内联、特化 | `@_alwaysEmitIntoClient` |
| `@export(interface)` | 只导出可调用的符号，隐藏实现 | `@_neverEmitIntoClient` |

这些属性主要面向发布二进制框架、追求极致性能的库作者。应用开发者通常不需要碰它们；滥用 `@inline(always)` 只会让代码体积膨胀。

## section
title: "`@section` 与 `@used`：把数据放进指定的段"
en: Section placement control
line: 2
se: 0492
level: brief
short: "@section"
tags: section 段 linker 链接器 used 嵌入式 插件 静态初始化 constant
tldr: 把全局变量放进目标文件里指定名字的段（section），并用 `@used` 防止它被链接器当作“没人用”而删掉。常用于嵌入式开发和“链接器集合”式的插件注册。

```swift check=ok
#if objectFormat(MachO)
@section("__DATA,plugins")
#else
@section("plugins")
#endif
@used
let pluginVersion: Int = 3        // 初始值必须是编译期常量
```

新的 `#if objectFormat(MachO)`、`objectFormat(ELF)`、`objectFormat(COFF)` 条件用来处理不同目标文件格式对段名的不同规定。

## weak-let
title: "`weak let`：不可变的弱引用"
en: weak let
line: 1
se: 0481
flag: ImmutableWeakCaptures
level: key
short: weak let
tags: weak let 弱引用 Sendable 不可变 immutable 循环引用 capture 捕获
tldr: 以前 `weak` 只能配 `var`，于是带弱引用属性的类永远无法成为 `Sendable`。现在可以写 `weak let`：初始化之后不能再改，但对象释放后依然会自动变成 `nil`。

```swift title="以前：Sendable 类里的 weak var 必然报错" check=error
final class TreeNode: Sendable {
    weak var parent: TreeNode?

    init(parent: TreeNode?) {
        self.parent = parent
    }
}
```

```swift title="Swift 6.3：weak let" check=ok
final class TreeNode: Sendable {
    weak let parent: TreeNode?        // 只在初始化时赋值
    let name: String

    init(name: String, parent: TreeNode?) {
        self.name = name
        self.parent = parent
    }
}
```

upcoming feature `ImmutableWeakCaptures` 把同样的思路用在闭包捕获上：`[weak self]` 捕获的变量变成不可变的，这样的闭包就可以是 `@Sendable` 的。

## clock-epochs
title: 时钟纪元 `systemEpoch`
en: Clock epochs
line: 4
se: 0473
level: brief
short: 时钟纪元
tags: Clock ContinuousClock SuspendingClock epoch 纪元 时间 Instant
tldr: "`ContinuousClock` 和 `SuspendingClock` 新增 `systemEpoch` 属性，表示这台机器上该时钟的“零点”。"

```swift check=run
let clock = ContinuousClock()
let sinceEpoch = clock.now - clock.systemEpoch

```

纪元是“系统相关”的，在不同机器之间没有可比性，不适合序列化保存；它适合和系统其他计时 API（例如内核时间戳）做换算。
