## async-await
title: "`async` / `await`：可以暂停的函数"
en: Asynchronous functions with async/await
line: 1
se: 0296
since: 5.5
level: core
short: async/await
tags: async await 异步 挂起 挂起点 暂停 suspend try await throws 回调 completion handler 顶层代码
tldr: "`async` 函数可以在等待慢操作（网络、计时器、另一个任务）时**暂停**，而不会堵住所在的线程。每个可能暂停的地方都用 `await` 标出来，代码里一眼就能看到。"

在 Swift 5.5 之前，等待一个慢操作就得传一个 completion handler：结果稍后才在闭包里送到，错误处理也被拆散在各个回调里。`async` 函数则直接返回结果，调用者在可能要等的地方写上 `await`：

```swift title="用 await 调用 async 函数" check=run
func fetchTemperature(city: String) async -> Int {
    try? await Task.sleep(for: .milliseconds(100))   // 假装这是一次网络请求
    return city == "奥斯陆" ? 4 : 21
}

let oslo = await fetchTemperature(city: "奥斯陆")    // 在这里暂停，直到结果就绪
let rome = await fetchTemperature(city: "罗马")
print("奥斯陆 \(oslo)°C，罗马 \(rome)°C")
```

函数停在 `await` 上时，它所在的线程并没有被堵住：线程会去做别的工作，等结果就绪，函数再接着往下执行。也正因为如此，`await` 只能写在能够暂停的地方。普通的同步函数没法暂停，所以编译器会拒绝：

```swift title="同步函数里不能 await" check=error hl="4"
func fetchTemperature(city: String) async -> Int { 21 }

func report() {                                   // 一个普通的同步函数
    let rome = await fetchTemperature(city: "罗马")
    print(rome)
}
```

解决办法有两个：把 `report()` 也改成 `async`，或者在里面启动一个 `Task`，也就是[下一站](#f-task)。

错误处理还是你熟悉的样子。一个函数可以同时是 `async` 和 `throws`，调用时写 `try await`：

```swift title="async throws 与 try await" check=run
struct OfflineError: Error {}

func download(_ name: String) async throws -> String {
    if name.isEmpty { throw OfflineError() }
    try await Task.sleep(for: .milliseconds(50))
    return "\(name) 的内容"
}

do {
    print(try await download("notes.txt"))
    print(try await download(""))
} catch {
    print("失败：", error)
}
```

- `await` 标记的是**可能的挂起点**。两个 `await` 之间的代码不会被打断；跨过一个 `await`，期间可能有别的代码在运行。讲到 [actor](#f-actor) 时要记住这一点。
- 能写 `await` 的地方有：`async` 函数里、`Task { }` 里，以及 `main.swift` 或 Playground 的顶层。所以本站的示例可以直接 `await`。
- `for await item in sequence` 会逐个等待异步序列里的元素；[任务组](#f-structured)那一站会用到它。

::: quiz
? 在哪些地方可以直接调用 `await fetchTemperature(city:)`？
- 任何函数里都行，只要写上 `await`
+ `async` 函数里、`Task { }` 里，或者 `main.swift` 的顶层
- 只能在主线程上
> `await` 需要一个能够暂停的上下文。同步函数做不到，所以编译器会拒绝这次调用；这时改为启动一个 `Task`。
:::

## task
title: "`Task`：启动异步工作，也能取消它"
en: Tasks and cooperative cancellation
line: 1
se: 0304
since: 5.5
level: core
short: Task
tags: Task 任务 非结构化 unstructured detached value cancel 取消 协作式 cooperative isCancelled checkCancellation CancellationError
tldr: "`Task { }` 可以在任何地方启动异步工作，同步代码里也行。它会给你一个句柄：`await task.value` 等待结果，`task.cancel()` **请求**任务停下。取消是协作式的：任务得自己去检查。"

`Task` 是一个异步工作单元，和创建它的代码同时进行。创建它并不会等它完成；拿着句柄，稍后再取结果：

```swift title="启动任务，继续往下走，再取结果" check=run
func fetchScore() async -> Int {
    try? await Task.sleep(for: .milliseconds(100))
    return 42
}

let task = Task {                     // 排进队列，和下面的代码同时进行
    await fetchScore()
}
print("任务已创建，调用者继续往下走")
let score = await task.value          // 现在才等它的结果
print("得分：", score)
```

同步代码（比如按钮的点击处理）也是这样进入异步世界的：它不能 `await`，但总可以创建一个 `Task`。

### 取消

`cancel()` 不会强行终止任务。它只是设置一个标志，什么时候停下由任务自己的代码决定。`Task.sleep` 这类异步 API 会替你检查这个标志，并抛出 `CancellationError`：

```swift title="下载到一半取消" check=run expect="CancellationError()"
let download = Task {
    for chunk in 1...5 {
        print("正在下载第", chunk, "块")
        try await Task.sleep(for: .milliseconds(200))   // 发现被取消，就抛出错误
    }
    return "完成"
}

try? await Task.sleep(for: .milliseconds(500))
download.cancel()                                     // 只是请求，不是强行终止
do {
    print(try await download.value)
} catch {
    print("已停止：", error)
}
```

- 长时间干活、又不调用这类 API 的代码，得自己检查：`if Task.isCancelled { … }`，或者 `try Task.checkCancellation()`，后者会抛出 `CancellationError`。
- `Task { }` 会沿用创建它的代码所在的 actor：在主 actor 上创建，它就在主 actor 上运行。`Task.detached { }` 则不属于任何 actor。两者都会在 [6.0 的第一站](#f-swift6-mode)出现。
- 扔掉句柄，任务照样会跑完，只是你再也没法等它或取消它。（如果这样还会吞掉错误，6.4 会给出警告：见[被忽略的“会抛错的 Task”](#f-task-unused)。）

::: quiz
? 任务正处在一个很长的循环里，这个循环从不检查 `Task.isCancelled`，也不调用任何异步 API。这时调用 `task.cancel()` 会怎样？
- 任务立刻停下，不管运行到哪里
+ 循环会一直跑完：取消只是一个标志，需要任务自己去检查
- 程序因为 `CancellationError` 崩溃
> Swift 的取消是协作式的。`cancel()` 只是设置一个标志，什么时候去看它由任务自己决定。这也是 [6.4 的取消屏蔽](#f-cancel-shield)存在的原因：它让清理代码看不到这个标志。
:::

## structured
title: "`async let` 与任务组：结构化并发"
en: Structured concurrency
line: 1
se: 0304, 0317
since: 5.5
level: core
short: async let 与任务组
tags: 结构化并发 structured concurrency async let 子任务 child task 并行 parallel TaskGroup withTaskGroup withThrowingTaskGroup addTask for await
tldr: "`async let` 启动一个**子任务**，和后面的代码并行执行；任务组对任意数量的子任务做同样的事。子任务活不过父任务：父任务会等它们全部结束，取消父任务也会取消它们。"

连着写两个 `await`，它们会一个接一个地执行。如果两者互不依赖，`async let` 能让它们同时开始：

```swift title="先一个接一个，再并行" check=run expect="约 200 毫秒"
func fetch(_ name: String) async -> String {
    try? await Task.sleep(for: .milliseconds(200))   // 每次获取耗时 0.2 秒
    return name
}

func elapsed(since start: ContinuousClock.Instant) -> String {
    let ms = (ContinuousClock.now - start) / .milliseconds(1)
    return "约 \(Int((ms / 100).rounded()) * 100) 毫秒"
}

var start = ContinuousClock.now
let a = await fetch("A")
let b = await fetch("B")
print("一个接一个：", a, b, elapsed(since: start))

start = ContinuousClock.now
async let c = fetch("C")            // 立刻作为子任务开始
async let d = fetch("D")            // 也立刻开始
let (x, y) = await (c, d)           // 等两个都完成
print("并行：", x, y, elapsed(since: start))
```

如果子任务的数量要到运行时才知道，就用任务组。每次 `addTask` 启动一个子任务，`for await` 按子任务完成的先后收集结果：

```swift title="每个数一个子任务" check=run
func square(_ n: Int) async -> Int {
    try? await Task.sleep(for: .milliseconds(40 * (6 - n)))   // 数越大，完成得越早
    return n * n
}

let total = await withTaskGroup(of: Int.self) { group in
    for n in 1...5 {
        group.addTask { await square(n) }        // 每个数一个子任务
    }
    var sum = 0
    for await value in group {                   // 按子任务完成的先后顺序
        print("收到", value)
        sum += value
    }
    return sum
}
print("平方和：", total)
```

- **结构化**的意思是：子任务的生命周期嵌套在父任务的作用域里，就像局部变量一样。`withTaskGroup` 返回时，所有子任务都已结束；从没被 `await` 的 `async let`，会在作用域结束时被取消，并被等到结束。
- 取消父任务，会取消它所有的子任务。在 `withThrowingTaskGroup` 里，子任务的错误一旦被抛出任务组，还在运行的子任务都会被取消。
- [上一站](#f-task)的 `Task { }` 是**非结构化**的：它可以比创建它的代码活得更久，所以要你自己管理。
- [Swift 6.1](#f-taskgroup-infer) 起可以省略 `of: Int.self`。

::: quiz
? 一个函数写了 `async let x = work()`，但直到返回都没有写 `await x`。`work()` 会怎样？
- 它根本没有开始
- 函数返回后，它在后台继续运行
+ 它的子任务会被取消，函数要等它结束才返回
> 子任务活不过自己的作用域。从没被等待的 `async let` 会在作用域结束时被取消，然后被隐式地等待，所以不会有任务泄漏。
:::

## actor
title: "`actor`：自己守护自己状态的类型"
en: Actors
line: 1
se: 0306, 0313
since: 5.5
level: core
short: actor
tags: actor 隔离 isolation isolated nonisolated 可变状态 数据竞争 data race 串行 可重入 reentrancy await
tldr: actor 就像一个类，但它的可变状态**同一时刻只能被一个任务**访问。actor 外面的代码要用 `await` 才能进去，所以两个任务永远不会同时修改这份状态。

如果两个任务同时修改同一个类的实例，就是数据竞争：更新会丢失，甚至更糟。actor 让调用者排队，一次一个。下面一千个子任务给同一个计数器加一，一次也没有丢：

```swift title="并发加一 1000 次，一次不丢" check=run
actor Counter {
    private(set) var value = 0

    func increment() {          // 在 actor 内部：就是普通的同步代码
        value += 1
    }
}

let counter = Counter()
await withTaskGroup(of: Void.self) { group in
    for _ in 1...1000 {
        group.addTask { await counter.increment() }   // 从外部：要 await 才能进去
    }
}
print("最终值：", await counter.value)
```

在 actor 内部，方法直接使用它的状态。从外部访问，就是在调用另一个**隔离域**，需要 `await`。而从外部直接给 actor 的属性赋值，是完全不允许的，加了 `await` 也不行：

```swift title="不能从外部给 actor 的属性赋值" check=error hl="6"
actor Counter {
    var value = 0
}

func reset(_ counter: Counter) async {
    await counter.value = 0
}
```

照提示说的做：给 actor 加一个方法来完成修改。不碰可变状态的成员可以标成 `nonisolated`，用的时候就不需要 `await`：

```swift title="nonisolated：不需要 await" check=run
actor BankAccount {
    let number: String                 // 常量：没什么需要保护的
    private var balance = 0

    init(number: String) { self.number = number }

    func deposit(_ amount: Int) -> Int {
        balance += amount
        return balance
    }

    nonisolated var label: String {    // 只读取常量
        "账户 #\(number)"
    }
}

let account = BankAccount(number: "42")
print(account.label)                   // 不需要 await
print("余额：", await account.deposit(100))
```

- actor 和类一样是引用类型，但不能被继承，而且总是 [`Sendable`](#f-sendable) 的：它自己保护自己，所以四处传递是安全的。
- **可重入**：actor 的某个方法停在 `await` 上时，actor 可能会去执行别的调用。在 actor 方法里跨过一个 `await` 之后，不要以为状态还和之前一样。
- actor 没有自己专属的线程，它在共享的线程池上运行。等着进入 actor 时，挂起的只是你的任务，不会有线程被堵住。

::: quiz
? 一个 actor 方法先读取 `balance`，然后 `await` 一次网络请求，最后把 `balance` 写回去。需要注意什么？
- 不用注意：整个方法调用期间 actor 都是锁住的
+ 在 `await` 期间，actor 可能执行了别的调用，`balance` 也许已经变了
- 编译器要求这个方法必须是 `nonisolated`
> actor 是可重入的：一个调用停在 `await` 上时，actor 可以去执行别的调用。每次 `await` 之后重新读取状态，或者在 `await` 之前就把修改做完。
:::

## main-actor
title: "`@MainActor`：主线程的那个 actor"
en: Global actors and the main actor
line: 1
se: 0316
since: 5.5
level: core
short: "@MainActor"
tags: MainActor 主 actor 全局 actor global actor 主线程 main thread UI UIKit SwiftUI AppKit 隔离
tldr: "`@MainActor` 是一个**全局 actor**：整个程序共用的一个 actor，它在主线程上运行。给 UI 代码标上它，编译器就会保证这些代码只在主线程上执行。"

UI 框架只能在主线程上使用，所以 Swift 把主线程也建模成一个 actor：主 actor。给类型、函数或属性加上 `@MainActor`，它就隔离在这个 actor 上。来自同一个 actor 的调用直接进行；来自别处的调用要 `await`：

```swift title="同一个 actor 直接调用，别的隔离域要 await" check=run
@MainActor
final class ScoreBoard {
    var score = 0
    func add(_ points: Int) { score += points }
}

@MainActor
func tapButton(_ board: ScoreBoard) {
    board.add(1)                       // 同一个 actor：直接调用
}

func syncFromServer(_ board: ScoreBoard) async {   // 不属于任何 actor
    await board.add(10)                // 不同的 actor：用 await 切换过去
}

let board = ScoreBoard()
tapButton(board)                       // 顶层代码本来就在主 actor 上运行
await syncFromServer(board)
print("得分：", board.score)
```

忘了写 `await`，编译器会拦住你：

```swift title="不写 await 就调用主 actor" check=error hl="8"
@MainActor
final class ScoreBoard {
    var score = 0
    func add(_ points: Int) { score += points }
}

func syncFromServer(_ board: ScoreBoard) async {
    board.add(10)
}
```

- `@MainActor` 的类是 `Sendable` 的：主 actor 保护着它的状态，所以可以放心共享。
- SwiftUI 的视图和 UIKit 的视图控制器本来就是 `@MainActor` 的，`main.swift` 的顶层代码也是。
- 在主 actor 上启动的 `Task { }` 也在主 actor 上运行，所以从按钮点击开始一段异步工作，通常就这么写。
- [Swift 6.2](#f-default-isolation) 可以让整个模块默认就是 `@MainActor`，不必处处手写。

::: quiz
? 一个不属于任何 actor 的函数，要调用 `@MainActor` 类的方法。它需要写什么？
- 什么都不用写：方法会自己跑到主线程上
+ `await`，因为这次调用要进入主 actor
- 在调用外面包一层 `DispatchQueue.main.async { }`
> 调用另一个隔离域是异步的：调用者要切换到主 actor 上，主 actor 正忙时还得等一等。Swift 6 模式下，编译器会替你检查这一点。
:::

## sendable
title: "`Sendable`：什么能在隔离域之间传递"
en: Sendable and @Sendable closures
line: 1
se: 0302
since: 5.5
level: core
short: Sendable
tags: Sendable @Sendable 闭包 closure 隔离域 isolation domain 边界 数据竞争 data race 值类型 struct final class unchecked
tldr: 每个 actor，以及不属于任何 actor 的代码，都是各自的**隔离域**。一个值只有是 `Sendable` 的，才能从一个隔离域传到另一个，意思是两边同时使用它也安全。值类型通常是；带可变状态的类不是。

actor 保护的是自己的状态，那传进传出的值呢？把一个可变的类实例交给 actor，自己还接着用，两个隔离域就共享了同一个对象：又是数据竞争。在 Swift 6 模式下，编译器会抓住它：

```swift title="交出一个可变对象，自己还在用" check=error hl="12,13"
final class Draft {                     // 带可变状态的类：不是 Sendable
    var text = ""
}

actor Outbox {
    func send(_ draft: Draft) { print("发送：", draft.text) }
}

func compose(using outbox: Outbox) async {
    let draft = Draft()
    draft.text = "你好"
    await outbox.send(draft)             // 把它交给 actor 的隔离域……
    draft.text = "我改主意了"             // ……自己却还在改它
}
```

把 `Draft` 改成 `struct`，问题就消失了：actor 拿到的是自己的一份拷贝，两边各改各的：

```swift title="值类型会被复制：每个隔离域各有一份" check=ok
struct Draft {                          // 值类型：自动就是 Sendable
    var text = ""
}

actor Outbox {
    func send(_ draft: Draft) { print("发送：", draft.text) }
}

func compose(using outbox: Outbox) async {
    var draft = Draft()
    draft.text = "你好"
    await outbox.send(draft)             // actor 拿到自己的一份拷贝
    draft.text = "我改主意了"             // 只改了我们自己这份
}
```

如果 `compose` 交出 `draft` 之后再也不碰它，就连类的版本也能编译通过，因为 Swift 6 能证明已经没有别人在用它了。这就是 [6.0 的区域隔离](#f-region-sending)。

哪些类型是 `Sendable` 的？

| 类型 | 是否 Sendable |
| --- | --- |
| `Int`、`String`、`Bool`…… | 是 |
| 元素为 Sendable 值的数组、字典和可选值 | 是 |
| 所有存储属性都是 Sendable 的 `struct` 或 `enum` | 是。模块内部会自动推断；`public` 类型要显式声明 |
| `actor`，或者 `@MainActor` 的类 | 是：由 actor 保护状态 |
| 存储属性全是 Sendable 的 `let` 的 `final class` | 是，只要声明 `: Sendable` |
| 有 `var` 存储属性的类 | 否 |

闭包也会跨越隔离域。标了 `@Sendable` 的闭包类型可能和其他代码并发执行，所以它不能修改自己捕获的局部变量：

```swift title="@Sendable 闭包不能修改捕获的变量" check=error hl="4"
func countClicks() {
    var clicks = 0
    let onClick: @Sendable () -> Void = {   // 可能和其他代码并发执行
        clicks += 1
    }
    onClick()
}
```

- `@unchecked Sendable` 是在告诉编译器“相信我，同步我自己来做”，比如用锁。编译器从此不再检查这个类型，所以要慎用；有了 6.0 的 [`Mutex`](#f-synchronization)，大多时候都用不着它。
- 这些检查是逐步到位的：5.5 引入了这个协议，之后的 5.x 版本陆续以警告的形式加入检查（用 `-strict-concurrency=complete` 打开），Swift 6 语言模式把它们变成了错误。这正是 [6.0 的第一站](#f-swift6-mode)。

::: note 在 Xcode 里试？
这里的示例都按 Swift 6 语言模式编译。如果你的 target 还是 Swift 5 模式，本页的错误只会是警告，甚至根本不出现。去构建设置里看看 **Swift Language Version**。
:::

::: quiz
? 下面哪个类型**不是** `Sendable` 的？
- `struct Point { var x: Int; var y: Int }`
- `actor Store { var items: [String] = [] }`
+ `final class Box { var value = 0 }`
- `[String: Int]`
> 由 Sendable 部件组成的值类型是 Sendable 的，actor 则自己保护自己。带可变 `var` 的类可能同时被两个隔离域修改，所以它不是 Sendable，除非它自己保护这份状态（比如它本身就是 actor，或者用了 `Mutex`）。
:::

## where-async-runs
title: 异步函数在哪里运行？
en: Where non-actor-isolated async functions run
line: 1
se: 0338
since: 5.7
level: key
short: 在哪里运行
tags: 执行器 executor 全局并发执行器 线程池 thread pool 切换 hop 隔离 isolation nonisolated async 主线程
tldr: 异步函数按自己的**隔离**决定在哪里运行：actor 的方法在那个 actor 上，`@MainActor` 函数在主线程上，不属于任何 actor 的函数在**全局并发线程池**上。改变隔离的调用，就是一次“切换”。

同步函数在调用它的线程上运行。异步函数不一样：它在哪里运行，由它自己的隔离决定，而不是由调用者决定。看看主线程是怎么被离开、又被回到的：

```swift title="nonisolated 的 async 函数会离开主 actor" check=run expect="work() 运行在 线程池里的线程"
import Foundation

func whereAmI() -> String { Thread.isMainThread ? "主线程" : "线程池里的线程" }

func work() async {                               // 不属于任何 actor
    print("  work() 运行在", whereAmI())
}

@MainActor
func start() async {
    print("start() 运行在", whereAmI())
    await work()                                  // 切换：离开主 actor
    print("start() 恢复在", whereAmI())          // 切换回来
}

await start()
```

这条规则来自 Swift 5.7 的 SE-0338。在那之前，这样的函数会一直跑在调用它的 actor 上，可能让本该放到后台的工作占住主 actor。从 5.7 起，不属于任何 actor 的函数总是在全局并发线程池上运行，那是所有任务共用的一组线程。

这条规则很好预测，但有代价：传给 `work()` 的一切都要从主 actor 跨进另一个隔离域，所以必须是 [`Sendable`](#f-sendable) 的。很多 Swift 6 报错就出在这里，这也是 Swift 6.2 允许你翻转默认行为的原因。下面是打开 6.2 的 upcoming feature 之后的同一段代码：

```swift title="同一段代码，打开 NonisolatedNonsendingByDefault（Swift 6.2）" check=run flags="-swift-version 6 -enable-upcoming-feature NonisolatedNonsendingByDefault" expect="work() 运行在 主线程"
import Foundation

func whereAmI() -> String { Thread.isMainThread ? "主线程" : "线程池里的线程" }

func work() async {                               // 不属于任何 actor
    print("  work() 运行在", whereAmI())
}

@MainActor
func start() async {
    print("start() 运行在", whereAmI())
    await work()                                  // 现在留在调用者身边
    print("start() 恢复在", whereAmI())
}

await start()
```

- 切换的开销不大，但也不是免费的。更重要的是，每次切换都是一道边界，值要安全地跨过去。
- 在新的默认规则下，给函数标上 [`@concurrent`](#f-concurrent) 可以保留旧行为；不打开 upcoming feature 时，写 [`nonisolated(nonsending)`](#f-nonsending) 可以逐个函数采用新行为。
- 在[并发执行轨迹实验室](#lab-concurrency)里一步步对比两种规则。

::: note 在 Xcode 里试？
Xcode 26 新建的 App 工程默认开启 **Approachable Concurrency**，其中就包括 `NonisolatedNonsendingByDefault`。在这样的工程里，第一个示例的 `work()` 也会打印“主线程”：你看到的是 6.2 的规则。
:::

::: quiz

## borrowing-consuming
title: "`consume`、`borrowing` 与 `consuming`：说清楚值归谁"
en: Ownership with consume, borrowing, and consuming
line: 2
se: 0366, 0377
since: 5.9
level: key
short: borrowing · consuming
tags: ownership 所有权 consume borrowing consuming copy 复制 移动 生命周期 写时复制 copy-on-write 性能 参数修饰符 noncopyable 不可复制 deinit
tldr: Swift 会在需要的地方自动复制值、retain 引用，不跟你商量。Swift 5.9 让你可以自己说清楚：`consume x` 让变量的生命周期就此结束，把值交出去；`borrowing` 参数只读取调用者的值；`consuming` 参数则把值接管过来。

大多数时候你不用考虑所有权：实参要么被借用（函数只读，值还归调用者），要么被复制，而写时复制让复制很便宜。可在每次复制都要计较的地方，以及在 6.0 的[不可复制类型](#f-noncopyable-generics)里（它们根本不能复制），就得把话说明白。

`consume` 让局部变量的生命周期在写下它的地方结束，并把值交出去。下面的连接在被 consume 的那一刻就关闭了，而不是等到函数结束：

```swift title="consume 让生命周期提前结束" check=run
final class Connection {
    let name: String
    init(_ name: String) { self.name = name; print("打开", name) }
    deinit { print("关闭", name) }
}

func work() {
    let connection = Connection("db")
    print("在", connection.name, "上查询")
    _ = consume connection          // 生命周期到此结束，而不是在右花括号
    print("做别的事")
}
work()
```

`consume` 之后变量就没了，再用它就是编译错误：

```swift title="consume 之后又用" check=error hl="8,9"
final class Connection {
    let name: String
    init(_ name: String) { self.name = name }
}

func work() {
    let connection = Connection("db")
    _ = consume connection
    print(connection.name)
}
```

### 参数说明实参的去向

| 修饰符 | 函数 | 调用者 |
| --- | --- | --- |
| `borrowing` | 只读取这个值 | 继续持有它 |
| `consuming` | 接管这个值：可以修改、存起来或继续传下去 | 交出它，除非传的是一份复制 |
| `inout` | 原地修改调用者的值 | 看得到修改 |

不写修饰符时，Swift 替你选：大多数参数是借用的，而初始化器和 setter 的参数是消耗的，因为它们通常要把值存起来。自己写上 `borrowing` 或 `consuming`，还会关掉这个参数的隐式复制，函数里每一次复制都得写成 `copy`：

```swift title="借用的参数不会被偷偷复制" check=error hl="2"
func longestFirst(_ names: borrowing [String]) -> [String] {
    var sorted = names
    sorted.sort { $0.count > $1.count }
    return sorted
}
```

写成 `var sorted = copy names` 就能编译。`consuming` 参数则归函数所有。如果调用者再用 `consume` 交出它唯一的引用，数组就能原地增长，不必先复制一份：

```swift title="consume + consuming：存储被移交，而不是复制" check=run
func storage(of array: [Int]) -> UnsafeRawPointer? {     // 数组存放元素的位置
    array.withUnsafeBufferPointer { UnsafeRawPointer($0.baseAddress) }
}

func appending(_ x: Int, to array: consuming [Int]) -> [Int] {
    array.append(x)               // `array` 归函数所有，所以可以修改
    return array
}

func demo() {
    var numbers = Array(1...1_000)
    numbers.reserveCapacity(2_000)
    let before = storage(of: numbers)

    let a = appending(1_001, to: numbers)            // 后面还要用 `numbers`：append 只好复制
    print("不用 consume，还是同一块存储：\(storage(of: a) == before)")

    let b = appending(1_001, to: consume numbers)    // 交出唯一的引用
    print("用了 consume，还是同一块存储：\(storage(of: b) == before)")
}
demo()
```

- 方法也可以是 `borrowing`、`consuming` 或 `mutating` 的，这时修饰的是 `self`。`consuming func` 会用掉调用它的那个值，就像 [6.0 第一个所有权站](#f-noncopyable-generics)里的车票。
- `consume` 只能用于局部变量和参数，不能用于全局变量或存储属性。`main.swift` 里的顶层变量是全局变量，所以这些示例都放在函数里。
- 对普通类型，只有当性能分析显示热点代码里有复制或 retain/release 开销时，才值得用这些修饰符。不可复制类型（`~Copyable`，同样是 5.9 随 SE-0390 加入的）根本不能复制，所以在那里这些修饰符是必须写的，6.0 也正是在这之上继续扩展。
- 动手试试：[所有权沙盒](#lab-ownership)。

::: quiz
? `connection` 持有一个类实例。`_ = consume connection` 做了什么？
- 复制这个对象，然后释放那份复制
+ 让这个变量的生命周期在这一行结束，之后再用 `connection` 就是编译错误
- 即使还有别的引用指向它，也会销毁这个对象
> `consume` 结束的是绑定的生命周期，不是对象的。示例里 `connection` 是唯一的引用，所以对象在那一行就被释放了；如果还有别的变量引用它，对象会继续活着。

## some-any
title: "`some` 与 `any`：一个藏起来的类型，或者一个什么都能装的盒子"
en: Opaque and boxed protocol types
line: 3
se: 0335, 0341, 0346
since: 5.7
level: core
short: some · any
tags: some any 不透明类型 opaque 存在类型 existential 协议 泛型 盒子 主要关联类型 primary associated type Collection<Int> ExistentialAny 隐式打开
tldr: "`some Shape` 代表**一个**遵循 `Shape` 的具体类型：编译器知道是哪个，只是你不用写出来。`any Shape` 是一个**盒子**，能装任何遵循 `Shape` 的类型的值，每次装的类型都可以不同。默认用 `some`，需要混合不同类型时再用 `any`。"

把协议当类型用，在 Swift 里一直都可以。Swift 5.6 允许你把它写成 `any Shape`（SE-0335），5.7 又允许 `some Shape` 用在参数上，不再只能用于返回类型（SE-0341）。两者放在一起，区别就出来了：

```swift title="some：每次调用一个类型；any：混合多种类型" check=run
protocol Shape {
    func area() -> Double
}

struct Square: Shape {
    var side: Double
    func area() -> Double { side * side }
}

struct Circle: Shape {
    var radius: Double
    func area() -> Double { 3.14 * radius * radius }
}

func describe(_ shape: some Shape) -> String {     // 每次调用是一个具体类型，编译期就知道
    "\(type(of: shape))，面积 \(shape.area())"
}

let shapes: [any Shape] = [Square(side: 2), Circle(radius: 1)]   // 能装任何 Shape 的盒子
for shape in shapes {
    print(describe(shape))                         // 调用时盒子会被打开
}
```

参数位置的 `some Shape` 是泛型参数的简写，等价于 `func describe<S: Shape>(_ shape: S)`。用在返回类型上，它承诺函数总是返回同一个类型，只是不让调用者看到。SwiftUI 的 `some View` 就是这个意思，这也是下面的代码编译不过的原因：

```swift title="some：每条路径都得是同一个类型" check=error hl="15,17"
protocol Shape {
    func area() -> Double
}
struct Square: Shape {
    var side: Double
    func area() -> Double { side * side }
}
struct Circle: Shape {
    var radius: Double
    func area() -> Double { 3.14 * radius * radius }
}

func makeShape(round: Bool) -> some Shape {
    if round {
        return Circle(radius: 1)
    }
    return Square(side: 1)
}
```

如果函数确实要返回不同的类型，就把返回类型写成 `any Shape`。

`Collection`、`Sequence` 这样的协议在尖括号里声明了**主要关联类型**（SE-0346），所以 `some` 和 `any` 还能说明里面装的是什么：

```swift title="some Collection<Int>" check=run
func total(_ numbers: some Collection<Int>) -> Int {     // 任何集合都行，只要装的是 Int
    numbers.reduce(0, +)
}

print(total([1, 2, 3]))
print(total(1...10))
print(total(Set([5, 6])))
```

- `any` 是有代价的：盒子多了一层间接（大的值放在堆上），调用要查表，具体类型也丢了，两个 `any Equatable` 的值连 `==` 都没法比较。`some` 保留了类型，编译出来和泛型一样。
- 把 `any Shape` 传给 `some Shape` 参数时，盒子会被自动打开（SE-0352，Swift 5.7），第一个示例里的循环就是这样。
- 在 Swift 6 模式下，直接写 `Shape` 仍然表示 `any Shape`。upcoming feature `ExistentialAny` 会要求必须写出 `any`，见[这一区的最后一站](#f-upcoming-features)。
- 后面的站两种都会用到：[6.0 的类型化抛出](#f-typed-throws)里，`throws` 是 `throws(any Error)` 的简写；[6.0](#f-isolation-inherit) 的 `#isolation` 的类型是 `(any Actor)?`；[6.4](#f-optional-some) 允许写 `some Shape?`。

::: quiz
? 哪种类型能让一个数组同时装下 `Square` 和 `Circle`？
- `[some Shape]`
+ `[any Shape]`
- `[Shape.Type]`
> `some Shape` 是同一个具体类型，所以 `[some Shape]` 里的每个元素都得是那个类型。`any Shape` 给每个值套一个盒子，每个盒子可以装不同的类型。
:::

title: "宏：替你写代码的 `#` 和 `@`"
en: Macros

short: 宏

这张线路图上很多较新的 API 都是宏：Swift Testing 的 `@Test` 和 `#expect`、`@Observable`、`@DebugDescription`、`#isolation`，还有你可能正在往里粘贴示例的 `#Playground`。宏有点像一个在编译器里运行的函数：它拿到语法树形式的代码，返回更多代码，这些代码再和你的代码一起编译。

那些代码随时都能看到。在 Xcode 里右键点宏，选 **Expand Macro**；在命令行上，`-dump-macro-expansions` 这个开关会把它打印出来。下面是标准库的 `@TaskLocal` 宏，它把一个静态属性变成按任务区分的值：`withValue` 会为它的闭包里运行的所有代码设置这个值。

```swift title="@TaskLocal 写了什么" check=run flags="-swift-version 6 -Xfrontend -dump-macro-expansions"
enum Request {
    @TaskLocal static var id = "none"
}

func log(_ message: String) {
    print("[\(Request.id)] \(message)")
}

func handle() {
    Request.$id.withValue("A-42") {       // `$id` 是宏写出来的
        log("处理中")
    }
    log("空闲")
}

handle()
```

宏添加了两样东西：`id` 的 getter（**访问器**宏），以及旁边一个装着真正 `TaskLocal` 值的 `$id` 属性（**对等**宏，peer）。这两样在源代码里都看不到。

| 种类 | 写法 | 例子 | 添加的内容 |
| --- | --- | --- | --- |
| 独立表达式宏 | `#name(…)` | `#expect(x == 1)`、`#isolation` | 一个表达式，放在宏所在的位置 |
| 独立声明宏 | `#name(…)` | `#Playground { … }`、`#Preview { … }` | 新的声明 |
| 附加宏 | 写在声明前的 `@Name` | `@Observable`、`@Test`、`@TaskLocal` | 成员、访问器、对等声明、扩展、协议遵循 |

宏用关键字 `macro` 声明，写法很像函数，并指明由哪个模块实现。Xcode 的 Playgrounds 模块就是这样声明 `#Playground` 的：

```swift title="Xcode 的 Playgrounds 模块里 #Playground 的声明" check=none
@freestanding(declaration)
public macro Playground(
    _ name: String? = nil,
    body: @escaping @Sendable () async throws -> Void
) = #externalMacro(module: "PlaygroundMacros", type: "Playground")
```

实现部分，也就是 `PlaygroundMacros` 模块里的 `Playground` 类型，是一个用 swift-syntax 库写成的独立程序，由编译器作为插件运行。它的展开结果会把你的闭包当作 `@MainActor` 的异步闭包传下去，所以 `#Playground` 块里的代码运行在主 actor 上，而且可以用 `await`。用 SwiftPM 添加的宏包也是同样的机制；`swift package init --type macro` 可以创建一个。

- 宏的参数要先通过类型检查，宏才会运行；它写出来的代码还会再做一次类型检查。和 C 预处理器的宏不同，Swift 宏处理的是语法树，不是文本。
- 宏只会添加代码，从不修改或删除你写的代码。
- 宏插件在沙盒里运行，不能访问网络，也不能访问你的文件。第一次构建用到别人的宏的包时，Xcode 会请你确认是否信任它们。

tags: parameter pack 参数包 variadic generics 可变参数 泛型 each repeat 展开 元组 重载 ViewBuilder buildBlock
tldr: "`<each T>` 声明一个**类型参数包**：任意数量的泛型类型，每个都可以不同。`repeat` 会把一个模式对每个元素展开一次，所以一个泛型函数就能代替一整排针对 2 个、3 个、4 个……参数的重载。"

可变参数 `T...` 能接收任意数量的值，但它们必须是同一个类型。要组合不同类型的值，以前只能按个数逐个写重载：SwiftUI 的视图构建器就有从 1 个到 10 个视图的各个版本。今天的 SDK 里只声明了一个 `buildBlock<each Content>`。有了参数包，每个实参都保留自己的类型：

```swift title="一个函数，接收任意数量、类型各异的实参" check=run
func describe<each Value>(_ value: repeat each Value) -> [String] {
    var lines: [String] = []
    repeat lines.append(String(describing: each value))    // 每个实参执行一次
    return lines
}

print(describe(42, "Swift", 6.4, true))
print(describe())

func duplicate<each T>(_ value: repeat each T) -> (repeat (each T, each T)) {
    (repeat (each value, each value))
}

let pairs = duplicate(1, "a", true)
print(pairs)
print(type(of: pairs))                  // 每个类型都保留了下来：没有任何 Any
```

- `each T` 引用这个包；`repeat` 标出一个**模式**，对每个元素展开一次，所以 `repeat (each T, each T)` 会变成 `(Int, Int), (String, String), (Bool, Bool)`。
- 类型也可以带参数包（SE-0398），比如 `struct Row<each Column>`。
- [6.0](#f-pack-iteration) 加入了 `for … in repeat each`，遍历参数包会容易得多。

## observable
title: "`@Observable`：会报告变化的类"
en: Observation
line: 4
se: 0395
since: 5.9
level: key
short: "@Observable"
tags: Observation Observable 观察 withObservationTracking ObservationIgnored ObservableObject Published SwiftUI State Bindable 追踪 变化
tldr: 给类标上 `@Observable`，对它属性的读取就能被追踪。`withObservationTracking` 运行一个闭包，记下它读了哪些属性，在**这些**属性之一即将改变时回调你。SwiftUI 就是靠这个决定哪些视图要重绘。

在 Swift 5.9 之前，SwiftUI 的模型是一个 `ObservableObject`，每个属性都要加 `@Published`；其中任何一个变了，视图都会重绘，哪怕它根本没读那个属性：

```swift title="以前：ObservableObject 与 @Published" check=ok
import Combine

final class Cart: ObservableObject {
    @Published var items: [String] = []
    @Published var coupon: String?
}
```

Observation 模块用一个宏取代了它：不需要属性包装器，而且按属性追踪：

```swift title="只追踪你读过的属性" check=run
import Observation

@Observable
final class Cart {
    var items: [String] = []
    var coupon: String?
}

let cart = Cart()

withObservationTracking {
    print("显示", cart.items.count, "件商品")      // 只读了 `items`
} onChange: {
    print("items 即将改变")
}

cart.coupon = "SAVE10"          // 上面没读它：不回调
cart.items.append("书")         // 回调 onChange，一次
cart.items.append("笔")         // 已经回调过了：不再回调
print("现在", cart.items)
```

- `onChange` 在改变**之前**运行，而且只运行一次。想继续观察，就得再调用一次 `withObservationTracking`：[6.2 的 `Observations`](#f-observations) 把这一套包装成了异步序列，[6.4](#f-observation-tracking) 又给这个函数本身加了选项。
- `@Observable` 只能用在类上；用在结构体上，宏会报错。给属性标上 `@ObservationIgnored`，它就不参与追踪。
- 把宏展开（见[宏那一站](#f-macros)）就能看到它写了什么：一个隐藏的 `_$observationRegistrar`，以及把每次读写都报告给它的访问器。
- 在 SwiftUI 里，用 `@State` 而不是 `@StateObject` 持有 `@Observable` 模型，传给子视图时当普通属性传就行；`@Bindable` 可以为它的属性生成绑定。

::: note 在 Playground 里试？
把 `Cart` 声明在 `#Playground { }` 上面，也就是文件的顶层。`@Observable` 是用扩展宏添加协议遵循的，而在块里声明的类型是局部类型，不能有扩展宏。
:::

::: quiz
? 一个视图的 `body` 读了 `cart.items`，从没读过 `cart.coupon`。`Cart` 是 `@Observable` 的，`coupon` 改变时会怎样？
- 视图重绘，就像任何 `ObservableObject` 视图一样
+ 什么也不发生：视图只追踪它的 `body` 实际读过的属性
- 应用崩溃，因为 `coupon` 没有注册
> Observation 按属性追踪。SwiftUI 在追踪中运行 `body`，所以只有 `items` 的改变会让这个视图失效。换成 `ObservableObject`，任何 `@Published` 属性的改变都会。
:::

## clock-duration
title: "`Duration` 与时钟：把时间当成类型"
en: Clock, Instant, and Duration
line: 4
se: 0329
since: 5.7
level: brief
short: Duration · Clock
tags: Duration Clock 时钟 ContinuousClock SuspendingClock Instant measure sleep 时间 超时 timeout 秒 毫秒 截止时间
tldr: "`Duration` 是带单位的一段时间，比如 `.seconds(2)` 或 `.milliseconds(250)`，可以相加、比较、相除。时钟负责报时：`ContinuousClock().now` 是一个 `Instant`，两个时刻相减得到一个 `Duration`。"

```swift title="时长、时刻与计时" check=run
let timeout: Duration = .seconds(2) + .milliseconds(500)
print(timeout, timeout / 5, timeout > .seconds(2))

let clock = ContinuousClock()
let elapsed = await clock.measure {               // 这个闭包用了多久？
    try? await Task.sleep(for: .milliseconds(120))
}
print(elapsed >= .milliseconds(120))

let start = clock.now                             // 一个 Instant：这个时钟上的某个时刻
try await clock.sleep(until: start + .milliseconds(50))
print(clock.now - start >= .milliseconds(50))     // Instant − Instant = Duration
```

- 并发各站里一直在用的 `Task.sleep(for:)` 接收的就是 `Duration`。旧的 `Task.sleep(nanoseconds:)` 接收的是一个光秃秃的 `UInt64`。
- `Duration` 除以 `Duration` 得到 `Double`：`elapsed / .milliseconds(1)` 就是以毫秒计的时间。[`async let` 那一站](#f-structured)就是这样给各次请求计时的。
- `ContinuousClock` 在设备休眠时也继续计时；`SuspendingClock` 会跟着停下。超时和现实世界里的截止时间，用连续时钟。
- [6.3](#f-clock-epochs) 给这两种时钟都加了 `systemEpoch`。

## upcoming-features
title: Upcoming feature：明天的规则，一条一条地先用上
en: Upcoming feature flags
line: 6
se: 0362
since: 5.8
level: key
short: Upcoming feature
tags: upcoming feature 开关 flag enable-upcoming-feature enableUpcomingFeature hasFeature 语言模式 language mode Swift 6 ExistentialAny Approachable Concurrency 迁移 源码兼容
tldr: 会让现有代码编译不过的改动，要等到下一个**语言模式**才生效。每个改动另外还有一个名字，比如 `ExistentialAny`；从 Swift 5.8 起，可以用 `-enable-upcoming-feature` 单独开启这一项。这张线路图上需要某个开关的站，会在标签里写出它的名字。

决定代码按哪套规则编译的是语言模式，而不是编译器版本。Swift 6 模式基本上就是这样一组改动的合集，它们是在 5.x 各版本里一条一条攒起来的。代码可以用 `#if hasFeature(…)` 检查某一项是否开启：

```swift title="这段代码是按哪些特性编译的？" check=run
#if hasFeature(StrictConcurrency)
print("StrictConcurrency               开")
#else
print("StrictConcurrency               关")
#endif

#if hasFeature(ExistentialAny)
print("ExistentialAny                  开")
#else
print("ExistentialAny                  关")
#endif

#if hasFeature(NonisolatedNonsendingByDefault)
print("NonisolatedNonsendingByDefault  开")
#else
print("NonisolatedNonsendingByDefault  关")
#endif
```

Swift 6 模式包含 `StrictConcurrency` 和另外 14 个 upcoming feature。列表里的另外两项不属于 Swift 6 模式，所以在你开启之前一直关着。一旦开启，今天就能用上它们的规则。比如 `ExistentialAny` 会把每一个没写 `any` 就当类型用的协议标出来：

```swift title="开启 ExistentialAny" check=warning flags="-swift-version 6 -enable-upcoming-feature ExistentialAny" hl="5"
protocol Shape {
    func area() -> Double
}

func totalArea(_ shapes: [Shape]) -> Double {
    shapes.reduce(0) { $0 + $1.area() }
}
```

在包里，按 target 列出要开启的特性：

```swift file=Package.swift check=none
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "MyApp",
    targets: [
        .target(
            name: "Core",
            swiftSettings: [
                .enableUpcomingFeature("ExistentialAny"),
                .enableUpcomingFeature("InternalImportsByDefault"),
            ]
        ),
    ]
)
```

### 还在路上的

Swift 6.4 的编译器知道六个 Swift 6 模式还不包含的 upcoming feature（`swiftc -print-supported-features` 会列出它们）。每一个在这张线路图上都有对应的站：

| Upcoming feature | 改变了什么 | 站点 |
| --- | --- | --- |
| `ExistentialAny` | 当类型用的协议必须写成 `any P` | [`some` 与 `any`](#f-some-any) |
| `InternalImportsByDefault` | 普通的 `import` 等于 `internal import` | [6.0](#f-import-access) |
| `MemberImportVisibility` | 扩展里的成员只在导入了其模块的文件里可见 | [6.1](#f-member-import) |
| `InferIsolatedConformances` | `@MainActor` 类型的协议遵循隔离在主 actor 上 | [6.2](#f-isolated-conformances) |
| `NonisolatedNonsendingByDefault` | 非隔离的异步函数在调用者的 actor 上运行 | [6.2](#f-nonsending) |
| `ImmutableWeakCaptures` | 用 `[weak x]` 捕获的变量不能重新赋值 | [6.3](#f-weak-let) |

- 在 Xcode 里，这些特性是构建设置，位于 **Swift Compiler - Upcoming Features**。Xcode 26 的 **Approachable Concurrency** 设置会一次开启其中一组，包括 `NonisolatedNonsendingByDefault` 和 `InferIsolatedConformances`，所以在新建的 Xcode 26 项目里，第一个示例会为 `NonisolatedNonsendingByDefault` 打印“开”。
- `-enable-experimental-feature` 是另一回事：那是还没做完的特性，随时可能改变或消失。
- [6.2 的 `swift package migrate`](#f-swiftpm-62) 可以替你完成开启某个特性所需的修改。
- 下一站是 [6.0](#f-swift6-mode)，它的第一站就是开启整个 Swift 6 模式。
