## async-await
title: "`async` / `await`：可以暂停的函数"
en: Asynchronous functions with async/await
line: 1
se: 0296
since: 5.5
level: core
short: async/await
tags: async await 异步 挂起 挂起点 暂停 suspend try await throws 回调 completion handler 顶层代码
tldr: "`async` 函数可以在等待慢操作（网络、计时器、另一个任务）时**暂停**，而不会堵住所在的线程。每个可能暂停的地方都用 `await` 标出来，代码里一眼就能看到。"

在 Swift 5.5 之前，等待一个慢操作就得传一个 completion handler：结果稍后才在闭包里送到，错误处理也被拆散在各个回调里。`async` 函数则直接返回结果，调用者在可能要等的地方写上 `await`：

```swift title="用 await 调用 async 函数" check=run
func fetchTemperature(city: String) async -> Int {
    try? await Task.sleep(for: .milliseconds(100))   // 假装这是一次网络请求
    return city == "奥斯陆" ? 4 : 21
}

let oslo = await fetchTemperature(city: "奥斯陆")    // 在这里暂停，直到结果就绪
let rome = await fetchTemperature(city: "罗马")
print("奥斯陆 \(oslo)°C，罗马 \(rome)°C")
```

函数停在 `await` 上时，它所在的线程并没有被堵住：线程会去做别的工作，等结果就绪，函数再接着往下执行。也正因为如此，`await` 只能写在能够暂停的地方。普通的同步函数没法暂停，所以编译器会拒绝：

```swift title="同步函数里不能 await" check=error hl="4"
func fetchTemperature(city: String) async -> Int { 21 }

func report() {                                   // 一个普通的同步函数
    let rome = await fetchTemperature(city: "罗马")
    print(rome)
}
```

解决办法有两个：把 `report()` 也改成 `async`，或者在里面启动一个 `Task`，也就是[下一站](#f-task)。

错误处理还是你熟悉的样子。一个函数可以同时是 `async` 和 `throws`，调用时写 `try await`：

```swift title="async throws 与 try await" check=run
struct OfflineError: Error {}

func download(_ name: String) async throws -> String {
    if name.isEmpty { throw OfflineError() }
    try await Task.sleep(for: .milliseconds(50))
    return "\(name) 的内容"
}

do {
    print(try await download("notes.txt"))
    print(try await download(""))
} catch {
    print("失败：", error)
}
```

- `await` 标记的是**可能的挂起点**。两个 `await` 之间的代码不会被打断；跨过一个 `await`，期间可能有别的代码在运行。讲到 [actor](#f-actor) 时要记住这一点。
- 能写 `await` 的地方有：`async` 函数里、`Task { }` 里，以及 `main.swift` 或 Playground 的顶层。所以本站的示例可以直接 `await`。
- `for await item in sequence` 会逐个等待异步序列里的元素；[任务组](#f-structured)那一站会用到它。

::: quiz
? 在哪些地方可以直接调用 `await fetchTemperature(city:)`？
- 任何函数里都行，只要写上 `await`
+ `async` 函数里、`Task { }` 里，或者 `main.swift` 的顶层
- 只能在主线程上
> `await` 需要一个能够暂停的上下文。同步函数做不到，所以编译器会拒绝这次调用；这时改为启动一个 `Task`。
:::

## task
title: "`Task`：启动异步工作，也能取消它"
en: Tasks and cooperative cancellation
line: 1
se: 0304
since: 5.5
level: core
short: Task
tags: Task 任务 非结构化 unstructured detached value cancel 取消 协作式 cooperative isCancelled checkCancellation CancellationError
tldr: "`Task { }` 可以在任何地方启动异步工作，同步代码里也行。它会给你一个句柄：`await task.value` 等待结果，`task.cancel()` **请求**任务停下。取消是协作式的：任务得自己去检查。"

`Task` 是一个异步工作单元，和创建它的代码同时进行。创建它并不会等它完成；拿着句柄，稍后再取结果：

```swift title="启动任务，继续往下走，再取结果" check=run
func fetchScore() async -> Int {
    try? await Task.sleep(for: .milliseconds(100))
    return 42
}

let task = Task {                     // 排进队列，和下面的代码同时进行
    await fetchScore()
}
print("任务已创建，调用者继续往下走")
let score = await task.value          // 现在才等它的结果
print("得分：", score)
```

同步代码（比如按钮的点击处理）也是这样进入异步世界的：它不能 `await`，但总可以创建一个 `Task`。

### 取消

`cancel()` 不会强行终止任务。它只是设置一个标志，什么时候停下由任务自己的代码决定。`Task.sleep` 这类异步 API 会替你检查这个标志，并抛出 `CancellationError`：

```swift title="下载到一半取消" check=run expect="CancellationError()"
let download = Task {
    for chunk in 1...5 {
        print("正在下载第", chunk, "块")
        try await Task.sleep(for: .milliseconds(200))   // 发现被取消，就抛出错误
    }
    return "完成"
}

try? await Task.sleep(for: .milliseconds(500))
download.cancel()                                     // 只是请求，不是强行终止
do {
    print(try await download.value)
} catch {
    print("已停止：", error)
}
```

- 长时间干活、又不调用这类 API 的代码，得自己检查：`if Task.isCancelled { … }`，或者 `try Task.checkCancellation()`，后者会抛出 `CancellationError`。
- `Task { }` 会沿用创建它的代码所在的 actor：在主 actor 上创建，它就在主 actor 上运行。`Task.detached { }` 则不属于任何 actor。两者都会在 [6.0 的第一站](#f-swift6-mode)出现。
- 扔掉句柄，任务照样会跑完，只是你再也没法等它或取消它。（如果这样还会吞掉错误，6.4 会给出警告：见[被忽略的“会抛错的 Task”](#f-task-unused)。）

::: quiz
? 任务正处在一个很长的循环里，这个循环从不检查 `Task.isCancelled`，也不调用任何异步 API。这时调用 `task.cancel()` 会怎样？
- 任务立刻停下，不管运行到哪里
+ 循环会一直跑完：取消只是一个标志，需要任务自己去检查
- 程序因为 `CancellationError` 崩溃
> Swift 的取消是协作式的。`cancel()` 只是设置一个标志，什么时候去看它由任务自己决定。这也是 [6.4 的取消屏蔽](#f-cancel-shield)存在的原因：它让清理代码看不到这个标志。
:::

## structured
title: "`async let` 与任务组：结构化并发"
en: Structured concurrency
line: 1
se: 0304, 0317
since: 5.5
level: core
short: async let 与任务组
tags: 结构化并发 structured concurrency async let 子任务 child task 并行 parallel TaskGroup withTaskGroup withThrowingTaskGroup addTask for await
tldr: "`async let` 启动一个**子任务**，和后面的代码并行执行；任务组对任意数量的子任务做同样的事。子任务活不过父任务：父任务会等它们全部结束，取消父任务也会取消它们。"

连着写两个 `await`，它们会一个接一个地执行。如果两者互不依赖，`async let` 能让它们同时开始：

```swift title="先一个接一个，再并行" check=run expect="约 200 毫秒"
func fetch(_ name: String) async -> String {
    try? await Task.sleep(for: .milliseconds(200))   // 每次获取耗时 0.2 秒
    return name
}

func elapsed(since start: ContinuousClock.Instant) -> String {
    let ms = (ContinuousClock.now - start) / .milliseconds(1)
    return "约 \(Int((ms / 100).rounded()) * 100) 毫秒"
}

var start = ContinuousClock.now
let a = await fetch("A")
let b = await fetch("B")
print("一个接一个：", a, b, elapsed(since: start))

start = ContinuousClock.now
async let c = fetch("C")            // 立刻作为子任务开始
async let d = fetch("D")            // 也立刻开始
let (x, y) = await (c, d)           // 等两个都完成
print("并行：", x, y, elapsed(since: start))
```

如果子任务的数量要到运行时才知道，就用任务组。每次 `addTask` 启动一个子任务，`for await` 按子任务完成的先后收集结果：

```swift title="每个数一个子任务" check=run
func square(_ n: Int) async -> Int {
    try? await Task.sleep(for: .milliseconds(40 * (6 - n)))   // 数越大，完成得越早
    return n * n
}

let total = await withTaskGroup(of: Int.self) { group in
    for n in 1...5 {
        group.addTask { await square(n) }        // 每个数一个子任务
    }
    var sum = 0
    for await value in group {                   // 按子任务完成的先后顺序
        print("收到", value)
        sum += value
    }
    return sum
}
print("平方和：", total)
```

- **结构化**的意思是：子任务的生命周期嵌套在父任务的作用域里，就像局部变量一样。`withTaskGroup` 返回时，所有子任务都已结束；从没被 `await` 的 `async let`，会在作用域结束时被取消，并被等到结束。
- 取消父任务，会取消它所有的子任务。在 `withThrowingTaskGroup` 里，子任务的错误一旦被抛出任务组，还在运行的子任务都会被取消。
- [上一站](#f-task)的 `Task { }` 是**非结构化**的：它可以比创建它的代码活得更久，所以要你自己管理。
- [Swift 6.1](#f-taskgroup-infer) 起可以省略 `of: Int.self`。

::: quiz
? 一个函数写了 `async let x = work()`，但直到返回都没有写 `await x`。`work()` 会怎样？
- 它根本没有开始
- 函数返回后，它在后台继续运行
+ 它的子任务会被取消，函数要等它结束才返回
> 子任务活不过自己的作用域。从没被等待的 `async let` 会在作用域结束时被取消，然后被隐式地等待，所以不会有任务泄漏。
:::

## actor
title: "`actor`：自己守护自己状态的类型"
en: Actors
line: 1
se: 0306, 0313
since: 5.5
level: core
short: actor
tags: actor 隔离 isolation isolated nonisolated 可变状态 数据竞争 data race 串行 可重入 reentrancy await
tldr: actor 就像一个类，但它的可变状态**同一时刻只能被一个任务**访问。actor 外面的代码要用 `await` 才能进去，所以两个任务永远不会同时修改这份状态。

如果两个任务同时修改同一个类的实例，就是数据竞争：更新会丢失，甚至更糟。actor 让调用者排队，一次一个。下面一千个子任务给同一个计数器加一，一次也没有丢：

```swift title="并发加一 1000 次，一次不丢" check=run
actor Counter {
    private(set) var value = 0

    func increment() {          // 在 actor 内部：就是普通的同步代码
        value += 1
    }
}

let counter = Counter()
await withTaskGroup(of: Void.self) { group in
    for _ in 1...1000 {
        group.addTask { await counter.increment() }   // 从外部：要 await 才能进去
    }
}
print("最终值：", await counter.value)
```

在 actor 内部，方法直接使用它的状态。从外部访问，就是在调用另一个**隔离域**，需要 `await`。而从外部直接给 actor 的属性赋值，是完全不允许的，加了 `await` 也不行：

```swift title="不能从外部给 actor 的属性赋值" check=error hl="6"
actor Counter {
    var value = 0
}

func reset(_ counter: Counter) async {
    await counter.value = 0
}
```

照提示说的做：给 actor 加一个方法来完成修改。不碰可变状态的成员可以标成 `nonisolated`，用的时候就不需要 `await`：

```swift title="nonisolated：不需要 await" check=run
actor BankAccount {
    let number: String                 // 常量：没什么需要保护的
    private var balance = 0

    init(number: String) { self.number = number }

    func deposit(_ amount: Int) -> Int {
        balance += amount
        return balance
    }

    nonisolated var label: String {    // 只读取常量
        "账户 #\(number)"
    }
}

let account = BankAccount(number: "42")
print(account.label)                   // 不需要 await
print("余额：", await account.deposit(100))
```

- actor 和类一样是引用类型，但不能被继承，而且总是 [`Sendable`](#f-sendable) 的：它自己保护自己，所以四处传递是安全的。
- **可重入**：actor 的某个方法停在 `await` 上时，actor 可能会去执行别的调用。在 actor 方法里跨过一个 `await` 之后，不要以为状态还和之前一样。
- actor 没有自己专属的线程，它在共享的线程池上运行。等着进入 actor 时，挂起的只是你的任务，不会有线程被堵住。

::: quiz
? 一个 actor 方法先读取 `balance`，然后 `await` 一次网络请求，最后把 `balance` 写回去。需要注意什么？
- 不用注意：整个方法调用期间 actor 都是锁住的
+ 在 `await` 期间，actor 可能执行了别的调用，`balance` 也许已经变了
- 编译器要求这个方法必须是 `nonisolated`
> actor 是可重入的：一个调用停在 `await` 上时，actor 可以去执行别的调用。每次 `await` 之后重新读取状态，或者在 `await` 之前就把修改做完。
:::

## main-actor
title: "`@MainActor`：主线程的那个 actor"
en: Global actors and the main actor
line: 1
se: 0316
since: 5.5
level: core
short: "@MainActor"
tags: MainActor 主 actor 全局 actor global actor 主线程 main thread UI UIKit SwiftUI AppKit 隔离
tldr: "`@MainActor` 是一个**全局 actor**：整个程序共用的一个 actor，它在主线程上运行。给 UI 代码标上它，编译器就会保证这些代码只在主线程上执行。"

UI 框架只能在主线程上使用，所以 Swift 把主线程也建模成一个 actor：主 actor。给类型、函数或属性加上 `@MainActor`，它就隔离在这个 actor 上。来自同一个 actor 的调用直接进行；来自别处的调用要 `await`：

```swift title="同一个 actor 直接调用，别的隔离域要 await" check=run
@MainActor
final class ScoreBoard {
    var score = 0
    func add(_ points: Int) { score += points }
}

@MainActor
func tapButton(_ board: ScoreBoard) {
    board.add(1)                       // 同一个 actor：直接调用
}

func syncFromServer(_ board: ScoreBoard) async {   // 不属于任何 actor
    await board.add(10)                // 不同的 actor：用 await 切换过去
}

let board = ScoreBoard()
tapButton(board)                       // 顶层代码本来就在主 actor 上运行
await syncFromServer(board)
print("得分：", board.score)
```

忘了写 `await`，编译器会拦住你：

```swift title="不写 await 就调用主 actor" check=error hl="8"
@MainActor
final class ScoreBoard {
    var score = 0
    func add(_ points: Int) { score += points }
}

func syncFromServer(_ board: ScoreBoard) async {
    board.add(10)
}
```

- `@MainActor` 的类是 `Sendable` 的：主 actor 保护着它的状态，所以可以放心共享。
- SwiftUI 的视图和 UIKit 的视图控制器本来就是 `@MainActor` 的，`main.swift` 的顶层代码也是。
- 在主 actor 上启动的 `Task { }` 也在主 actor 上运行，所以从按钮点击开始一段异步工作，通常就这么写。
- [Swift 6.2](#f-default-isolation) 可以让整个模块默认就是 `@MainActor`，不必处处手写。

::: quiz
? 一个不属于任何 actor 的函数，要调用 `@MainActor` 类的方法。它需要写什么？
- 什么都不用写：方法会自己跑到主线程上
+ `await`，因为这次调用要进入主 actor
- 在调用外面包一层 `DispatchQueue.main.async { }`
> 调用另一个隔离域是异步的：调用者要切换到主 actor 上，主 actor 正忙时还得等一等。Swift 6 模式下，编译器会替你检查这一点。
:::

## sendable
title: "`Sendable`：什么能在隔离域之间传递"
en: Sendable and @Sendable closures
line: 1
se: 0302
since: 5.5
level: core
short: Sendable
tags: Sendable @Sendable 闭包 closure 隔离域 isolation domain 边界 数据竞争 data race 值类型 struct final class unchecked
tldr: 每个 actor，以及不属于任何 actor 的代码，都是各自的**隔离域**。一个值只有是 `Sendable` 的，才能从一个隔离域传到另一个，意思是两边同时使用它也安全。值类型通常是；带可变状态的类不是。

actor 保护的是自己的状态，那传进传出的值呢？把一个可变的类实例交给 actor，自己还接着用，两个隔离域就共享了同一个对象：又是数据竞争。在 Swift 6 模式下，编译器会抓住它：

```swift title="交出一个可变对象，自己还在用" check=error hl="12,13"
final class Draft {                     // 带可变状态的类：不是 Sendable
    var text = ""
}

actor Outbox {
    func send(_ draft: Draft) { print("发送：", draft.text) }
}

func compose(using outbox: Outbox) async {
    let draft = Draft()
    draft.text = "你好"
    await outbox.send(draft)             // 把它交给 actor 的隔离域……
    draft.text = "我改主意了"             // ……自己却还在改它
}
```

把 `Draft` 改成 `struct`，问题就消失了：actor 拿到的是自己的一份拷贝，两边各改各的：

```swift title="值类型会被复制：每个隔离域各有一份" check=ok
struct Draft {                          // 值类型：自动就是 Sendable
    var text = ""
}

actor Outbox {
    func send(_ draft: Draft) { print("发送：", draft.text) }
}

func compose(using outbox: Outbox) async {
    var draft = Draft()
    draft.text = "你好"
    await outbox.send(draft)             // actor 拿到自己的一份拷贝
    draft.text = "我改主意了"             // 只改了我们自己这份
}
```

如果 `compose` 交出 `draft` 之后再也不碰它，就连类的版本也能编译通过，因为 Swift 6 能证明已经没有别人在用它了。这就是 [6.0 的区域隔离](#f-region-sending)。

哪些类型是 `Sendable` 的？

| 类型 | 是否 Sendable |
| --- | --- |
| `Int`、`String`、`Bool`…… | 是 |
| 元素为 Sendable 值的数组、字典和可选值 | 是 |
| 所有存储属性都是 Sendable 的 `struct` 或 `enum` | 是。模块内部会自动推断；`public` 类型要显式声明 |
| `actor`，或者 `@MainActor` 的类 | 是：由 actor 保护状态 |
| 存储属性全是 Sendable 的 `let` 的 `final class` | 是，只要声明 `: Sendable` |
| 有 `var` 存储属性的类 | 否 |

闭包也会跨越隔离域。标了 `@Sendable` 的闭包类型可能和其他代码并发执行，所以它不能修改自己捕获的局部变量：

```swift title="@Sendable 闭包不能修改捕获的变量" check=error hl="4"
func countClicks() {
    var clicks = 0
    let onClick: @Sendable () -> Void = {   // 可能和其他代码并发执行
        clicks += 1
    }
    onClick()
}
```

- `@unchecked Sendable` 是在告诉编译器“相信我，同步我自己来做”，比如用锁。编译器从此不再检查这个类型，所以要慎用；有了 6.0 的 [`Mutex`](#f-synchronization)，大多时候都用不着它。
- 这些检查是逐步到位的：5.5 引入了这个协议，之后的 5.x 版本陆续以警告的形式加入检查（用 `-strict-concurrency=complete` 打开），Swift 6 语言模式把它们变成了错误。这正是 [6.0 的第一站](#f-swift6-mode)。

::: note 在 Xcode 里试？
这里的示例都按 Swift 6 语言模式编译。如果你的 target 还是 Swift 5 模式，本页的错误只会是警告，甚至根本不出现。去构建设置里看看 **Swift Language Version**。
:::

::: quiz
? 下面哪个类型**不是** `Sendable` 的？
- `struct Point { var x: Int; var y: Int }`
- `actor Store { var items: [String] = [] }`
+ `final class Box { var value = 0 }`
- `[String: Int]`
> 由 Sendable 部件组成的值类型是 Sendable 的，actor 则自己保护自己。带可变 `var` 的类可能同时被两个隔离域修改，所以它不是 Sendable，除非它自己保护这份状态（比如它本身就是 actor，或者用了 `Mutex`）。
:::

## where-async-runs
title: 异步函数在哪里运行？
en: Where non-actor-isolated async functions run
line: 1
se: 0338
since: 5.7
level: key
short: 在哪里运行
tags: 执行器 executor 全局并发执行器 线程池 thread pool 切换 hop 隔离 isolation nonisolated async 主线程
tldr: 异步函数按自己的**隔离**决定在哪里运行：actor 的方法在那个 actor 上，`@MainActor` 函数在主线程上，不属于任何 actor 的函数在**全局并发线程池**上。改变隔离的调用，就是一次“切换”。

同步函数在调用它的线程上运行。异步函数不一样：它在哪里运行，由它自己的隔离决定，而不是由调用者决定。看看主线程是怎么被离开、又被回到的：

```swift title="nonisolated 的 async 函数会离开主 actor" check=run expect="work() 运行在 线程池里的线程"
import Foundation

func whereAmI() -> String { Thread.isMainThread ? "主线程" : "线程池里的线程" }

func work() async {                               // 不属于任何 actor
    print("  work() 运行在", whereAmI())
}

@MainActor
func start() async {
    print("start() 运行在", whereAmI())
    await work()                                  // 切换：离开主 actor
    print("start() 恢复在", whereAmI())          // 切换回来
}

await start()
```

这条规则来自 Swift 5.7 的 SE-0338。在那之前，这样的函数会一直跑在调用它的 actor 上，可能让本该放到后台的工作占住主 actor。从 5.7 起，不属于任何 actor 的函数总是在全局并发线程池上运行，那是所有任务共用的一组线程。

这条规则很好预测，但有代价：传给 `work()` 的一切都要从主 actor 跨进另一个隔离域，所以必须是 [`Sendable`](#f-sendable) 的。很多 Swift 6 报错就出在这里，这也是 Swift 6.2 允许你翻转默认行为的原因。下面是打开 6.2 的 upcoming feature 之后的同一段代码：

```swift title="同一段代码，打开 NonisolatedNonsendingByDefault（Swift 6.2）" check=run flags="-swift-version 6 -enable-upcoming-feature NonisolatedNonsendingByDefault" expect="work() 运行在 主线程"
import Foundation

func whereAmI() -> String { Thread.isMainThread ? "主线程" : "线程池里的线程" }

func work() async {                               // 不属于任何 actor
    print("  work() 运行在", whereAmI())
}

@MainActor
func start() async {
    print("start() 运行在", whereAmI())
    await work()                                  // 现在留在调用者身边
    print("start() 恢复在", whereAmI())
}

await start()
```

- 切换的开销不大，但也不是免费的。更重要的是，每次切换都是一道边界，值要安全地跨过去。
- 在新的默认规则下，给函数标上 [`@concurrent`](#f-concurrent) 可以保留旧行为；不打开 upcoming feature 时，写 [`nonisolated(nonsending)`](#f-nonsending) 可以逐个函数采用新行为。
- 在[并发执行轨迹实验室](#lab-concurrency)里一步步对比两种规则。

::: note 在 Xcode 里试？
Xcode 26 新建的 App 工程默认开启 **Approachable Concurrency**，其中就包括 `NonisolatedNonsendingByDefault`。在这样的工程里，第一个示例的 `work()` 也会打印“主线程”：你看到的是 6.2 的规则。
:::

- 在主线程上，和调用者一样
+ 在全局并发线程池上

> 从 SE-0338 起，不属于任何 actor 的函数在全局并发执行器上运行，那是所有任务共用的线程池；不会为每次调用新建线程。6.2 的 `nonisolated(nonsending)` 可以让它留在调用者的 actor 上。
:::

## checked-continuation
title: "续体：把回调式 API 包装成 `async`"
en: Continuations for interfacing async tasks with synchronous code
line: 1
se: 0300
since: 5.5
level: brief
short: 续体
tags: 续体 continuation withCheckedContinuation withCheckedThrowingContinuation CheckedContinuation resume 回调 callback completion handler 桥接 旧 API
tldr: "`withCheckedContinuation` 能把 completion handler 风格的 API 变成 `async` 函数：任务会暂停，直到回调调用 `resume`，而且必须**恰好调用一次**。"

```swift title="从 completion handler 到 await" check=run
import Foundation

// 一个用 completion handler 回报结果的老 API
func legacyFetch(_ id: Int, completion: @escaping @Sendable (String) -> Void) {
    DispatchQueue.global().asyncAfter(deadline: .now() + 0.1) {
        completion("记录 #\(id)")
    }
}

func fetch(_ id: Int) async -> String {
    await withCheckedContinuation { continuation in
        legacyFetch(id) { value in
            continuation.resume(returning: value)   // 恰好恢复一次
        }
    }
}

print(await fetch(7))
```

- 可能失败的 API，用 `withCheckedThrowingContinuation` 和 `resume(throwing:)`。
- “Checked”的意思是误用会在运行时被发现：恢复两次会让程序崩溃；续体没被恢复就被丢掉时，会打印一条警告，否则等着它的任务会永远挂在那里。
- [6.4 的 `Continuation`](#f-continuation) 把“恢复两次”变成了编译期错误。
