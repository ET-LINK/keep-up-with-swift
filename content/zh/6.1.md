## nonisolated-types
title: "`nonisolated` 可以修饰类型与扩展"
en: Allow nonisolated to prevent global actor inference
line: 1
se: 0449
level: key
short: nonisolated 类型
tags: nonisolated extension 扩展 MainActor 推断 inference 协议一致性
tldr: 以前 `nonisolated` 只能写在单个属性或方法上。现在可以写在整个 `extension` 上，一次让里面所有成员都不受 actor 隔离；写在类型上，还能阻止编译器自动推断出全局 actor。

```swift title="以前：每个成员都要单独写一遍 nonisolated" check=ok
@MainActor
struct Product {
    var name: String
    var price: Double
}

extension Product: CustomStringConvertible, Equatable {
    nonisolated var description: String { "\(name) ¥\(price)" }
    nonisolated static func == (a: Product, b: Product) -> Bool { a.name == b.name }
}
```

```swift title="Swift 6.1：一个 nonisolated extension 搞定" check=ok hl="7"
@MainActor
struct Product {
    var name: String
    var price: Double
}

nonisolated extension Product: CustomStringConvertible, Equatable {
    var description: String { "\(name) ¥\(price)" }
    static func == (a: Product, b: Product) -> Bool { a.name == b.name }
}
```

另一个用途是阻止“隔离推断”。遵循一个 `@MainActor` 协议的类型，会被自动推断成 `@MainActor`，于是在其他地方用它就处处要 `await`：

```swift title="遵循了 @MainActor 协议，类型被悄悄推断成主 actor 隔离" check=error
@MainActor protocol Screen {}

struct Settings: Screen {
    var theme = "dark"
    func export() -> String { theme }
}

func backup(_ s: Settings) -> String {
    s.export()
}
```

```swift title="用 nonisolated struct 明确拒绝推断" check=ok
@MainActor protocol Screen {}

nonisolated struct Settings: Screen {
    var theme = "dark"
    func export() -> String { theme }
}

func backup(_ s: Settings) -> String {
    s.export()
}
```

## taskgroup-infer
title: 任务组自动推断结果类型
en: Allow TaskGroup's ChildTaskResult type to be inferred
line: 1
se: 0442
level: brief
short: 任务组推断
tags: withTaskGroup TaskGroup 推断 inference of: 子任务
tldr: `withTaskGroup(of: Int.self)` 里的 `of:` 现在可以省略，编译器会根据 `addTask` 的闭包推断子任务的结果类型。

```swift title="以前：必须写 of:" check=run
let total = await withTaskGroup(of: Int.self) { group in
    for n in 1...5 { group.addTask { n * n } }
    var sum = 0
    for await square in group { sum += square }
    return sum
}
print(total)
```

```swift title="现在：省略 of:" check=run hl="1"
let total = await withTaskGroup { group in
    for n in 1...5 { group.addTask { n * n } }
    var sum = 0
    for await square in group { sum += square }
    return sum
}
print(total)
```

顺带一提：这里用 `for await` 而不是 `group.reduce(0, +)`。在主 actor 上直接调用 `reduce` 这类 `nonisolated async` 方法，会把任务组“送”到别的线程，Swift 6 模式下会报 `sending 'group' risks causing data races`。这正是 [6.2 的 nonsending](#f-nonsending) 要解决的问题。

## trailing-commas
title: 尾随逗号几乎到处都能写
en: Allow trailing comma in comma-separated lists
line: 3
se: 0439
level: key
short: 尾随逗号
tags: trailing comma 逗号 参数列表 元组 泛型 捕获列表 diff
tldr: 数组和字典字面量一直允许最后多一个逗号。Swift 6.1 把它扩展到参数列表、实参列表、元组、泛型参数列表、闭包捕获列表和字符串插值。

最大的好处是 diff 更干净：增删最后一个参数时，只改一行。代码生成工具（宏、插件）也不用再特殊处理最后一项。

```swift check=run
func makeLabel(
    text: String,
    size: Double,
    bold: Bool,          // ← 形参列表
) -> String {
    "\(text)·\(size)·\(bold)"
}

let label = makeLabel(
    text: "Swift",
    size: 17,
    bold: true,          // ← 实参列表
)

let point = (
    x: 1,
    y: 2,                // ← 元组
)

struct Pair<
    First,
    Second,              // ← 泛型参数列表
> {}

let show = { [label, point,] in    // ← 捕获列表
    print(label, point)
}
show()
```

条件列表是个例外：`if a, b, { }` 依然不允许，因为尾随的逗号会让 `{` 产生歧义。

```swift title="if 的条件列表不能有尾随逗号" check=error script
let a = true, b = false
if a, b, {
    print("不行")
}
```

## metatype-keypaths
title: 元类型键路径：键路径可以指向静态属性
en: Metatype keypaths
line: 3
se: 0438
level: brief
short: 静态键路径
tags: keypath 键路径 static 静态属性 metatype 元类型
tldr: 写 `\Theme.Type.accent` 就能得到指向静态属性的键路径，和实例属性的键路径用法一致。

```swift check=run
struct Theme {
    static let accent = "orange"
    static let font = "SF Pro"
}

let accentPath = \Theme.Type.accent
print(Theme.self[keyPath: accentPath])

let all: [KeyPath<Theme.Type, String>] = [\.accent, \.font]
print(all.map { Theme.self[keyPath: $0] })
```

## objc-implementation
title: "`@objc @implementation`：用 Swift 实现 Objective-C 类"
en: Objective-C implementations in Swift
line: 5
se: 0436
level: key
short: "@implementation"
tags: Objective-C objc implementation 混编 迁移 头文件 category
tldr: 头文件保持不变，用一个带 `@objc @implementation` 的 Swift 扩展替代 `.m` 文件里的 `@implementation`。老项目可以一个类、一个 category 地逐步迁移到 Swift。

```objc file=MyView.h check=none
// 头文件不变，Objective-C 和 Swift 的调用方都照常使用
@interface MyView : NSView
- (void)reload;
@end
```

```swift title="MyView.swift：在 Swift 里写实现" check=none
@objc @implementation
extension MyView {
    func reload() {
        print("用 Swift 实现的 reload")
    }
}
```

编译器会检查 Swift 实现和头文件里的声明是否一一对应：漏实现、多实现、签名不匹配都会报错。实现 category 时写 `@objc(CategoryName) @implementation extension MyView`。

## member-import
title: 成员导入可见性
en: Member import visibility
line: 3
se: 0444
flag: MemberImportVisibility
level: brief
short: 成员导入
tags: import 可见性 visibility extension 扩展 MemberImportVisibility
tldr: 以前只要模块里**任意一个文件**导入了某个模块，它通过扩展添加的方法在**所有文件**里都能用。开启 `MemberImportVisibility` 后，只有真正写了 `import` 的文件才能看到这些成员。

```swift file=Report.swift check=none
// 另一个文件 A.swift 写了 import FancyStrings（它给 String 扩展了 shout()）

// Report.swift 没有 import FancyStrings：
let title = "hello".shout()
// 以前：可以编译（悄悄依赖了别的文件的 import）
// 开启 MemberImportVisibility 后：报错，并提示你加上 import FancyStrings
```

这让依赖关系变得诚实：删除一个文件不会莫名其妙地让另一个文件编译失败，也避免了不同模块同名扩展方法的歧义。

## warning-flags
title: 精确控制警告：`-Werror` 与诊断分组
en: Precise control flags over compiler warnings
line: 6
se: 0443
level: brief
short: 警告分组
tags: warnings 警告 -Werror -Wwarning warnings-as-errors 诊断分组 diagnostic group
tldr: 以前只能“全部警告当错误”或者“全部不当”。现在可以按**诊断分组**单独控制，例如所有警告都升级为错误，唯独“已废弃 API”保持为警告。

```shell check=none
# 所有警告视为错误，但“使用了已废弃的 API”保持为警告
swiftc -warnings-as-errors -Wwarning DeprecatedDeclaration main.swift

# 只把某一组警告升级为错误
swiftc -Werror DeprecatedDeclaration main.swift
```

分组名就是编译器诊断末尾方括号里的名字。本站展示的真实编译输出里随处可见，比如 `[#DeprecatedDeclaration]`、`[#RegionIsolation]`，每个分组都有一篇官方文档。6.2 起 SwiftPM 也能这样设置（见 [6.2](#f-swiftpm-62)），6.4 更是可以直接在源码里用 [`@diagnose`](#f-diagnose) 控制。

## package-traits
title: SwiftPM 包特性（Package Traits）
en: Package traits
line: 6
se: 0450
level: key
short: 包特性
tags: SwiftPM package traits 特性 条件编译 可选依赖 Embedded WebAssembly
tldr: 一个包可以声明若干“特性”（trait），使用者按需开启或关闭。特性可以控制条件编译和可选依赖，让同一个包在服务器、嵌入式、WebAssembly 等环境里提供不同的功能。

```swift file=Package.swift check=none
// swift-tools-version: 6.1
import PackageDescription

let package = Package(
    name: "Logging",
    traits: [
        .trait(name: "JSON", description: "输出 JSON 格式的日志"),
        .trait(name: "Embedded", description: "为嵌入式环境裁剪功能"),
        .default(enabledTraits: ["JSON"]),       // 默认开启 JSON
    ],
    targets: [
        .target(name: "Logging"),
    ]
)
```

```swift title="使用方：只开启需要的特性" check=none
.package(url: "https://github.com/example/logging", from: "1.0.0", traits: ["Embedded"])
```

```swift title="包内代码：特性就是编译条件" check=none
#if JSON
func format(_ message: String) -> String { #"{"msg": "\#(message)"}"# }
#else
func format(_ message: String) -> String { message }
#endif
```

## testing-61
title: Swift Testing：作用域特性与可检查的错误
en: Test scoping traits & returned errors
line: 6
level: brief
short: 测试作用域
tags: Swift Testing TestScoping trait #expect throws 错误 setUp tearDown
tldr: `#expect(throws:)` 和 `#require(throws:)` 现在会返回捕获到的错误，方便进一步检查；遵循 `TestScoping` 的自定义特性可以在测试前后执行准备和清理逻辑。

```swift check=ok testing
import Testing

enum LoginError: Error, Equatable {
    case wrongPassword(attemptsLeft: Int)
}

func login(_ password: String) throws(LoginError) {
    throw .wrongPassword(attemptsLeft: 2)
}

@Test func reportsAttemptsLeft() {
    let error = #expect(throws: LoginError.self) {
        try login("123456")
    }
    #expect(error == .wrongPassword(attemptsLeft: 2))   // 返回值就是那个错误
}

struct MockServer: TestTrait, TestScoping {
    func provideScope(
        for test: Test,
        testCase: Test.Case?,
        performing function: @Sendable () async throws -> Void
    ) async throws {
        print("启动模拟服务器")
        try await function()
        print("关闭模拟服务器")
    }
}

extension Trait where Self == MockServer {
    static var mockServer: Self { Self() }
}

@Test(.mockServer) func fetchProfile() async {
    #expect(true)
}
```
